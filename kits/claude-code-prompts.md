# AX YOUR BODY · Part 3·4 지시문 킷 (Stitch · Claude Code)

이 킷은 교재 Part 3·4의 [실습 안내]에 나오는 지시문의 전체 문장입니다. 교재에 나온 지시문 이름으로 찾습니다. `{ }` 부분을 자기 내용으로 바꿔 붙여 넣습니다. 교재 본문의 지시문은 예제 프로필에 맞춰 줄인 것이고, 이 킷은 어느 프로필에나 쓸 수 있는 기본형입니다.

사용 원칙
1. **요구 → 확인 → 수정**을 반복합니다. 한 번에 완벽한 결과를 기대하지 않습니다.
2. 한 지시에는 한 가지 목적만 담습니다.
3. 파일은 `@경로`로 가리킵니다. 예) `@context/service-structure.md`
4. 결과는 항상 브라우저로 직접 열어 눌러 보고, 발견한 점을 「테마별로 만든 첫 프로토타입과 버전 기록」에 적습니다.
5. 큰 변경 전에는 지금 파일을 다른 이름으로 복사해 둡니다. 예) `prototype-first-{테마이름}-before-states.html`
6. 실제 이름·연락처·실제 신체 수치를 쓰지 않습니다. 실제 수치로 실습했다면 배포 전에 「배포 전 개인정보 점검·정적 배포 준비 지시문」으로 반드시 걷어 냅니다.

├── design/
│   ├── DESIGN-{테마이름}.md          ← 쇼핑 목록의 테마 이름 (예: DESIGN-calm-record-board.md)
│   └── DESIGN-{테마이름}.md          ← 두 번째 테마 (예: DESIGN-sport-brand.md)
├── data/                            ← 고른 프로필의 CSV 4개
├── prototype-first-{테마이름}.html   ← Day 3 테마별 첫 프로토타입 (테마마다 하나)

└── deploy/                          ← index.html + favicon.svg 만 (배포용)

## Stitch 테마별 시안 생성 지시문

```
AX YOUR BODY라는 웹 서비스의 화면 시안을 만들어 줘.
AI를 활용해 PT 코칭을 대체하거나 효과를 높이는 "AI 리서치 + 기록 관리 보드"야.

[사용자]
{프로필 이름 · 한 줄 소개}

[만들 화면]
{화면 이름}
이 화면의 목적: {화면 목록의 목적 한 줄}
꼭 보여야 할 정보: {대상 객체와 속성}

[디자인 규칙]
아래 DESIGN.md의 색·글꼴·간격·구성 방침을 그대로 따라 줘.
{design/DESIGN-{테마이름}.md 내용 붙여 넣기 또는 첨부}

[화면에 쓸 이름]
{용어 대조표의 사용자 용어들}
```

이어서 줄 수 있는 변경 지시 예: "정보를 위에서 아래로 중요한 순서대로 다시 배치해 줘", "모바일 너비에서도 같은 순서로 보이게 해 줘".

## 서비스 구조를 넘기고 첫 프로토타입을 만드는 지시문

```
지금부터 AX YOUR BODY의 클릭 가능한 HTML 프로토타입을 만들 거야.
먼저 아래 파일을 모두 읽고, 이해한 내용을 다섯 줄로 요약해 줘. 내가 요약을 확인한 뒤에 만들기 시작해.

- 서비스와 사용자: @context/service-structure.md
- 핵심 흐름·화면 목록·상태 화면 목록: @context/screen-flow.md
- 디자인 규칙: @design/DESIGN-{테마이름}.md
- 화면에 넣을 데이터: @data/ 폴더의 CSV

[만들 결과]
- prototype-first-{테마이름}.html 한 파일 안에 화면 목록의 화면을 모두 만들고, 메뉴와 버튼으로 흐름 순서대로 이동하며 눌러 볼 수 있게
- 화면에 쓰는 이름은 service-structure.md의 "화면에 쓸 말"만 사용
- 데이터는 data 폴더의 값을 사용
- 외부 라이브러리 없이 HTML·CSS(필요하면 간단한 JavaScript)만으로, 파일을 더블클릭하면 열리게

만들기 전에 모르는 것이 있으면 먼저 물어봐 줘.
만든 뒤에는 만든 화면 목록과, screen-flow.md에 있었지만 아직 만들지 않은 화면 목록을 보여 줘.
```

## 테마별 프로토타입 추가 생성 지시문

```
@prototype-first-{첫 테마이름}.html 의 화면 구조와 내용은 그대로 두고,
디자인 규칙만 @design/DESIGN-{둘째 테마이름}.md 로 바꾼 버전을 prototype-first-{둘째 테마이름}.html 로 새로 만들어 줘.
prototype-first-{첫 테마이름}.html 은 고치지 마.
두 버전에서 달라진 점을 영역별(상단 메뉴, 카드, 표, 버튼, 글꼴)로 짧게 정리해 줘.
```

## 빈 상태·오류 등 상태 화면과 신뢰 요소 추가 지시문

```
큰 변경을 하기 전에 지금 @prototype-first-{테마이름}.html 을 prototype-first-{테마이름}-before-states.html 로 복사해 둬.
그다음 @context/screen-flow.md 의 "상태 화면 목록"을 보고 prototype-first-{테마이름}.html 에 다음 상태를 추가해 줘.

- 빈 상태: {예: 이번 주 기록이 하나도 없을 때 — 탓하지 말고 다음 행동 하나만 제안}
- 오류: {예: 기록 저장에 실패했을 때 — 입력한 내용은 지우지 않기}
- 로딩: {예: AI 판단을 만드는 중일 때}
- 이상치: {예: 체중이 하루 만에 1kg 넘게 바뀌었을 때 — 측정 조건을 확인하도록 안내}

화면 위쪽에 "상태 미리 보기" 전환 버튼을 달아, 정상·빈 상태·오류·로딩·이상치를 바꿔 가며 볼 수 있게 해 줘.
같은 작업을 prototype-first-{다른 테마이름}.html 에도 해 줘.
```

### 이어서 · 신뢰 요소 넣기 (Part 3의 신뢰 설계 실습)

```
@prototype-first-{테마이름}.html 에서 AI가 판단하거나 처방하는 화면({화면 이름})에 다음 다섯 가지를 넣어 줘.
1. 판단: AI가 내린 결론 한 문장
2. 근거: 그 결론에 쓴 기록(날짜와 값)
3. 한계: 이 판단이 고려하지 못한 것
4. 전문가 확인 권장: 어떤 경우에 사람 전문가와 상의해야 하는지
5. 사용자의 선택: 판단을 따를지, 바꿀지, 미룰지 고르는 버튼
색만으로 구분하지 말고 라벨과 테두리 모양으로도 구분되게 해 줘.
```

## 나만의 DESIGN.md 단독 문서 보강 지시문

```
@my-own-DESIGN.md 문서만 있어도 다른 프로젝트에 단독으로 적용될 수 있도록 아래처럼 고쳐 줘.
---
1. 다른 파일이나 스타일 명세서, 작업 이력은 전혀 언급하지 말고, 이 문서만 읽고 이해할 수 있는 내용으로 보강
2. HTML 요소와 CSS 코드 예제를 빠짐없이 포함
3. 완성된 HTML 파일을 보지 않아도 되도록, 화면의 각 영역이 구조·역할·내용 면에서 어떤 요소로 어떻게 표현되는지 유형별로 정리
4. 색이 없어도(흑백) 구분이 유지되도록 하는 방침을 한 절로 추가
```

보강이 끝나면 새 대화에서 my-own-DESIGN.md 하나만 넘겨 새 화면을 만들게 해 보는 **재현 시험**을 하고, 결과를 「나만의 디자인 가이드(DESIGN.md)와 점검표」에 붙입니다.
