# AX YOUR BODY · Part 3·4 지시문 킷 (Stitch · Claude Code)

이 킷은 교재 Part 3·4의 [실습 안내]에 나오는 지시문의 전체 문장입니다. 교재에 나온 지시문 이름으로 찾습니다. `{ }` 부분을 자기 내용으로 바꿔 붙여 넣습니다. 교재 본문의 지시문은 예제 프로필에 맞춰 줄인 것이고, 이 킷은 어느 프로필에나 쓸 수 있는 기본형입니다.

> **교재 지시문을 그대로 붙여 넣지 마세요.** 교재 Part 3·4 지시문에 인쇄된 이름·날짜·값은 `{ }` 표시가 없어도 모두 예제 프로필의 것입니다.
> - Part 3(3.6·3.7, 김도현 예): 테마 이름 `bright-coaching` · `neat-basic` · `activity-record`, 파일 이름 `DESIGN-bright-coaching.md` · `prototype-first-neat-basic.html` 등, 날짜와 수치 10/15 86.8kg · 10/17·10/18 등
> - Part 4(4.2·4.3·4.6, 박준혁 예): 테마 이름 `calm-record-board` · `sport-brand` · `clinic-report`, 영역 지도의 줄 번호(12~48줄, 212~290줄 등), `m-athlete`, 스킬 이름 `workout-modal`, 10/26~11/01 디로드, 강조색 `#2F5D50`, `DESIGN-calm-record-board.md`
> - Part 4(4.4, 김도현 예): 10/15 회식, "이번 주 운동 2/3회" 같은 개선 이슈 / (4.7, 정하은 예): `f-athlete`
> 이 킷의 지시문을 쓰거나, 교재 지시문을 쓸 때는 이 단어들을 모두 내 테마 이름·내 영역 지도 줄 번호·내 프로필의 날짜와 값으로 바꿉니다.

사용 원칙
1. **요구 → 확인 → 수정**을 반복합니다. 한 번에 완벽한 결과를 기대하지 않습니다.
2. 한 지시에는 한 가지 목적만 담습니다.
3. 파일은 `@경로`로 가리킵니다. 예) `@context/service-structure.md`
4. 결과는 항상 브라우저로 직접 열어 눌러 보고, 발견한 점을 「테마별로 만든 첫 프로토타입과 버전 기록」에 적습니다.
5. 큰 변경 전에는 지금 파일을 다른 이름으로 복사해 둡니다. 예) `prototype-first-{테마이름}-before-states.html`
6. 실제 이름·연락처·실제 신체 수치를 쓰지 않습니다. 실제 수치로 실습했다면 배포 전에 「배포 전 개인정보 점검·정적 배포 준비 지시문」으로 반드시 걷어 냅니다.

## Stitch 테마별 시안 생성 지시문

교재 3.5절 예시(김도현 · 오늘 화면)와 같은 칸 순서입니다. 테마마다 `[디자인]` 줄만 바꾸고 나머지는 한 글자도 바꾸지 않아야 테마끼리 공정하게 비교됩니다.

```
AX YOUR BODY라는 개인 트레이닝 관리 웹 서비스의 "{화면 이름}" 화면 시안을 만들어 주세요.

[사용자] {프로필의 한 줄 소개}. 이 화면에서 {이 사람이 바로 하고 싶은 일}을 하고 싶어 합니다.
[화면 목적] {화면 목록의 목적 한 줄}
[들어갈 내용]
- {대상 객체·속성과 data 폴더의 실제 값. 이름은 용어 대조표의 사용자 용어로}
- {들어갈 내용 더}
- 주요 버튼 1개: "{버튼 이름}"
[디자인] 첨부한 {DESIGN-테마이름.md}의 규칙만 따라 주세요. 문서에 없는 색은 쓰지 마세요.
[형태] 데스크톱 화면 1장 (모바일 화면은 같은 프로젝트에서 이어서 요청)
```

- **DESIGN.md를 첨부할 때:** 테마가 바뀌면 `[디자인]` 줄의 파일 이름만 바꿉니다.
- **첨부가 안 되거나 처음이라 붙여 넣을 때:** `[디자인]` 줄을 "아래 DESIGN.md의 규칙만 따라 주세요. 문서에 없는 색은 쓰지 마세요."로 바꾸고, 지시문 맨 끝에 DESIGN.md 내용을 붙여 넣습니다. 테마가 바뀌면 붙여 넣은 내용만 바꿉니다.

이어서 줄 수 있는 변경 지시 예: "정보를 위에서 아래로 중요한 순서대로 다시 배치해 줘", "모바일 너비에서도 같은 순서로 보이게 해 줘".

## 서비스 구조를 넘기고 첫 프로토타입을 만드는 지시문

```
지금부터 AX YOUR BODY의 클릭 가능한 HTML 프로토타입을 만들 거야.
먼저 아래 파일을 모두 읽고, 이해한 내용을 다섯 줄로 요약해 줘. 내가 요약을 확인한 뒤에 만들기 시작해.

- 서비스와 사용자: @context/service-structure.md
- 핵심 흐름·화면 목록·상태 화면 목록: @context/screen-flow.md
- 디자인 규칙: @design/DESIGN-{테마이름}.md
- 화면에 넣을 데이터: @data/ 폴더의 CSV

[만들 결과]
- prototype-first-{테마이름}.html 한 파일 안에 screen-flow.md 화면 목록의 화면만 모두 만들고, 기본 흐름과 갈림길의 화살표대로 메뉴와 버튼을 이어 눌러 볼 수 있게
- 화면에 쓰는 이름은 service-structure.md의 "화면에 쓸 말"만 사용
- 수치는 data 폴더의 CSV 값만 사용. 없는 수치를 지어내지 말 것
- AI 판단 문장은 예시로 넣고, 어떤 기록을 근거로 했는지 함께 적기
- 디자인은 DESIGN-{테마이름}.md의 규칙만 따르고, 색만으로 의미를 구분하지 말 것
- 데스크톱과 모바일 폭 모두에서 보이게
- 외부 라이브러리 없이 HTML·CSS(필요하면 간단한 JavaScript)만으로, 파일을 더블클릭하면 열리게

만들기 전에 모르는 것이 있으면 먼저 물어봐 줘.
만든 뒤에는 만든 화면 목록과, screen-flow.md에 있었지만 아직 만들지 않은 화면 목록을 보여 줘.
```

## 테마별 프로토타입 추가 생성 지시문

```
@prototype-first-{첫 테마이름}.html 과 화면 구성·흐름·문구·데이터는 똑같이 두고,
디자인만 @design/DESIGN-{둘째 테마이름}.md 의 규칙으로 바꾼 prototype-first-{둘째 테마이름}.html 을 새로 만들어 줘.
prototype-first-{첫 테마이름}.html 은 고치지 마.
다 만든 뒤 두 파일에서 화면 구성이나 문구가 달라진 곳이 있으면 목록으로 알려 줘.
```

세 번째 테마가 있으면 같은 지시로 하나 더 만듭니다. 그 파일에도 아래 상태 화면과 신뢰 요소를 똑같이 넣습니다(Day 4 통합 때 세 파일 모두에서 영역을 가져올 수 있게).

## 빈 상태·오류 등 상태 화면과 신뢰 요소 추가 지시문

```
큰 변경을 하기 전에 지금 @prototype-first-{테마이름}.html 을 prototype-first-{테마이름}-before-states.html 로 복사해 둬.
그다음 @context/screen-flow.md 의 "상태 화면 목록"을 보고 prototype-first-{테마이름}.html 에 다음 상태를 추가해 줘.

- 빈 상태: {예: 이번 주 기록이 하나도 없을 때 — 탓하지 말고 다음 행동 하나만 제안}
- 오류: {예: 기록 저장에 실패했을 때 — 입력한 내용은 지우지 않기}
- 로딩: {예: AI 판단을 만드는 중일 때}
- 이상치: {예: 체중이 하루 만에 1kg 넘게 바뀌었을 때 — 측정 조건을 확인하도록 안내}

화면 맨 아래에 "상태 미리 보기" 전환 버튼을 달아, 정상·빈 상태·오류·로딩·이상치를 바꿔 가며 볼 수 있게 해 줘.
끝나면 나머지 테마 파일(prototype-first-{다른 테마이름}.html, 세 번째 테마가 있으면 그것도)에도 각각 같은 복사본을 만든 뒤 똑같이 해 줘.
```

### 이어서 · 신뢰 요소 넣기 (Part 3의 신뢰 설계 실습)

```
먼저 지금 @prototype-first-{테마이름}.html 을 prototype-first-{테마이름}-before-trust.html 로 복사해 둬.
그다음 prototype-first-{테마이름}.html 의 {화면 이름} 화면에 있는 AI 판단 카드를 다음 구조로 바꿔 줘.
1. 판단: 결론 한 문장 (카드 맨 위)
2. 근거: "근거" 라벨 + 판단에 쓴 기록의 종류·기간·값(data 폴더 CSV 기준) 목록
3. 한계: "한계" 라벨 + 빠진 기간이나 측정 조건이 다른 기록이 있으면 한 줄
4. 전문가 확인 권장: 통증·어지럼 같은 경우에만 라벨·아이콘·테두리 상자로
5. 사용자의 선택: "다른 안 보기" 버튼
근거·한계는 한 줄만 보이다가 "근거 자세히"를 누르면 펼쳐지게 해 줘.
색만으로 구분하지 말고, 다른 화면은 바꾸지 마.
```

같은 지시를 나머지 테마 파일에도 보내 두 테마를 비교합니다(파일 이름만 바꿉니다).

## 여러 테마 버전 통합 지시문

### 사전 단계 · 영역 지도 받기 (조사만)

```
이 폴더에 테마별 첫 프로토타입이 여러 개 있어: {파일 이름들, 예: prototype-first-calm-record-board.html, prototype-first-sport-brand.html}.
파일마다 화면을 영역으로 나누고, 영역 이름 · 시작 줄 · 끝 줄 · 한 줄 설명을 표로 정리해 줘.
이번에는 아무 파일도 고치지 마.
```

### 통합 지시

```
지금부터 여러 테마로 만든 프로토타입에서 장점만 뽑아 통합한 버전을 만들고 싶어.
결과는 새 파일 prototype-merged.html 에 만들고, 기존 prototype-first- 파일들은 고치지 마.
전체 뼈대(화면 폭, 영역 순서, 상단 메뉴 위치)는 {기준 파일 이름}.html 을 기준으로 해.
아래 번호 순서대로 영역을 가져와 줘. 줄 번호는 방금 만든 영역 지도 기준이야.
---
1. {영역 이름}: {파일}.html {시작}~{끝}줄
2. {영역 이름}: {파일}.html {시작}~{끝}줄
3. …
---
지킬 것
- 화면 문구와 영역 이름은 @context/service-structure.md 의 "화면에 쓸 말"에 있는 이름만 쓴다.
- 수치는 data 폴더의 CSV 값만 쓴다. 없는 수치를 지어내지 않는다.
- 색과 글꼴이 섞여도 지금은 그대로 둔다. 테마 통일은 나중에 따로 한다.
- 빈 상태·오류·로딩·이상치 화면(앞서 상태 화면 지시문으로 만든 것)은 해당 영역과 함께 옮긴다. 상태 화면이 없는 파일에서 가져온 영역은 지어내지 말고 목록으로 알려 준다.
다 옮긴 뒤, 아직 옮기지 않은 콘텐츠를 목록으로 정리하고 어떻게 처리할지 나에게 질문해 줘. 내가 답하기 전에는 더 고치지 마.
```

## 외부 디자인 요소 보강 지시문

```
아래에 붙인 지시문은 {출처 사이트}에서 복사한 "{요소 이름}" 디자인이야.
이 지시문을 {스킬 이름} 이라는 이름의 스킬로 저장해 줘.

작업 전에 prototype-merged.html 을 prototype-merged-before-skill.html 로 복사해 둬.
그다음 prototype-merged.html 의 {영역 이름} 영역(영역 지도의 줄 범위: {시작}~{끝}줄)에만 이 스킬을 적용해 줘.
- {이 영역에서 보여 줄 내용. 대상 객체 카드에 있는 속성만, data 폴더에 있는 값만}
- 색과 글꼴은 현재 프로토타입의 디자인 규칙을 따르고, 구조와 움직임만 가져와.
- 모달이 생기면 닫기 버튼, Esc 키, 바깥 누르기로 닫히게 해 줘.
- 원래 지시문의 상품·사진용 문구와 예시는 모두 내 서비스의 {대상 객체} 내용으로 바꿔.
- 다른 영역은 고치지 마. 끝나면 바뀐 줄 범위를 알려 줘.
---
{가져온 요소 지시문 붙여 넣기}
---
```

`{이 영역에서 보여 줄 내용}`은 대상 객체 카드의 속성에서 고릅니다. 데이터셋에 종목별로 한 값만 있는 항목(예: 운동인 `workout.csv`의 RPE)은 세트마다 넣지 말고 한 번만 보여 달라고 적습니다(교재 4.3).
