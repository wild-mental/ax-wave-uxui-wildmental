# DESIGN.md — AX YOUR BODY 샘플 (단정한 기본형)

> 이 문서는 교재의 예시로 새로 작성한 샘플 DESIGN.md입니다. 항목은 교재 3.3절 표와 같은 순서(분위기와 원칙 · 색 · 글꼴 · 간격과 배치 · 모양 · 부품 · 문구 톤 · 하지 말 것)로 썼습니다. 디자인 쇼핑의 "안전한 선택"으로 그대로 쓰거나, 쇼핑한 다른 DESIGN.md와 비교하는 기준으로 씁니다.
>
> - **먼저 읽을 곳:** 8. 하지 말 것과 2. 색 (교재 3.4절)
> - **이 문서가 정하지 않는 것:** 화면 목록, 메뉴, 영역의 순서 같은 **화면 구조**는 정하지 않습니다. 화면 구조는 내 `context/screen-flow.md`와 `context/service-structure.md`를 따릅니다. 이 문서는 그 구조를 어떤 색·글꼴·모양·부품으로 보여 줄지만 정합니다.
> - 다른 방향의 예가 필요하면 화면 구조까지 정해 둔 「DESIGN-axyourbody-sample-B.md」(디자인 B 버전)를 봅니다.

## 1. 분위기와 원칙

- **성격:** 차분한 코치. 사용자를 재촉하거나 탓하지 않고, 오늘 할 일 하나를 분명히 보여 준다.
- **원칙 1 — 한 화면 한 결정:** 화면마다 사용자가 내릴 결정 하나를 가장 위, 가장 크게 둔다. 숫자보다 "다음에 할 일"이 먼저 보인다.
- **원칙 2 — 근거가 보이는 AI:** AI의 판단·처방에는 언제나 근거와 한계를 함께 붙인다.
- **원칙 3 — 빈틈을 허용하는 기록:** 기록이 빠진 날도 자연스럽게 보이고, 다시 시작하는 행동 하나를 제안한다.
- **원칙 4 — 색 없이도 읽힌다:** 상태와 위계는 색뿐 아니라 글자 라벨·기호 모양·선 굵기로도 구분한다.

## 2. 색

| 역할 | 값 | 쓰는 곳 |
|---|---|---|
| 배경 | `#F7F7F5` | 페이지 바탕 |
| 표면 | `#FFFFFF` | 카드·입력칸 |
| 글자 | `#1D1F21` | 본문·제목 |
| 보조 글자 | `#5C6166` | 설명·단위 |
| 주색 | `#2F6B4F` | 화면당 주요 버튼 1개 · 선택된 메뉴 · 진행 막대 |
| 주의 | `#B5542B` | 이상치·확인 필요 (언제나 ⚠ 기호와 "확인 필요" 라벨을 함께) |
| 선 | `#E2E3DF` | 구분선·카드 테두리 |

- 위 일곱 가지 말고 다른 색은 쓰지 않는다.
- 성공·주의·오류는 색만으로 나누지 않는다. 기호(✓ ⚠ ✕)와 낱말 라벨을 함께 쓴다.
- 글자와 배경의 명도 대비는 본문 4.5:1 이상.
- 어두운 테마에서는 배경 `#141615`, 표면 `#1E2120`, 글자 `#ECEDEA`, 보조 글자 `#A3A8A4`, 선 `#2E322F`를 쓰고, 주색·주의 색은 명도만 한 단계 올린다.

## 3. 글꼴

| 용도 | 크기 / 굵기 / 줄 간격 |
|---|---|
| 화면 제목 | 24px / 700 / 1.3 |
| 카드 제목 | 17px / 600 / 1.4 |
| 본문 | 15px / 400 / 1.6 |
| 핵심 숫자 | 32px / 700 / 1.1 (고정폭 숫자) |
| 보조·단위 | 13px / 400 / 1.4 |

글꼴은 `Pretendard, "Noto Sans KR", system-ui, sans-serif` 순서로 지정한다. 숫자에는 `font-variant-numeric: tabular-nums`를 쓴다.

## 4. 간격과 배치

- 기본 간격 단위는 8px. 카드 안 여백 20px, 카드 사이 16px, 절 사이 32px.
- 데스크톱은 최대 너비 1120px, 12칸 그리드, 칸 사이 24px. 카드는 4칸 · 6칸 · 12칸 너비 가운데에서 고른다.
- 모바일(너비 600px 이하)은 한 열로 쌓고, 좌우 여백 16px. 쌓는 순서는 데스크톱의 위→아래, 왼쪽→오른쪽 순서와 같다.
- 현재 위치(선택된 메뉴)는 주색과 함께 굵은 밑줄 3px로 표시한다.
- 화면 안 영역의 순서와 메뉴 구성은 이 문서가 아니라 `screen-flow.md`의 화면 목록을 따른다.

## 5. 모양

- 모서리 둥글기: 카드 12px, 버튼·입력칸 8px, 칩 999px.
- 카드 테두리 1px 실선(`#E2E3DF`), 그림자는 쓰지 않는다.
- AI 판단 카드만 테두리 2px(주색)로 다른 카드와 구분한다.
- 점선은 "한계"처럼 보조 정보를 나누는 데만 쓴다.

## 6. 부품

### 주요 버튼

- 화면당 1개. 높이 48px, 주색 바탕에 흰 글자, 모서리 8px.
- 보조 버튼은 흰 바탕에 1px 테두리. 주요 버튼보다 크게 만들지 않는다.

### 핵심 지표 카드

```html
<section class="metric-card">
  <p class="metric-label">이번 주 훈련 강도</p>
  <p class="metric-value">중간 <span class="metric-unit">(RPE 평균 7.2)</span></p>
  <p class="metric-change"><span aria-hidden="true">▼</span> 지난주보다 낮음 · 디로드 주간</p>
</section>
```

```css
.metric-card { background:#FFFFFF; border:1px solid #E2E3DF; border-radius:12px; padding:20px; }
.metric-label { font-size:13px; color:#5C6166; margin:0 0 4px; }
.metric-value { font-size:32px; font-weight:700; line-height:1.1; margin:0; font-variant-numeric:tabular-nums; }
.metric-unit { font-size:15px; font-weight:400; color:#5C6166; }
.metric-change { font-size:13px; margin:8px 0 0; }
```

변화 방향은 ▲▼ 기호와 문장("지난주보다 낮음")을 함께 쓴다.

### AI 판단 카드 (판단 · 근거 · 한계 · 전문가 확인 권장 · 사용자의 선택)

```html
<article class="ai-card">
  <p class="ai-tag">AI 코치 판단</p>
  <h3>오늘은 하체 훈련 강도를 70%로 낮추세요</h3>
  <details>
    <summary>근거 자세히</summary>
    <p class="ai-label">근거</p>
    <ul><li>수면 기록: 최근 3일 평균 4.6시간</li><li>컨디션 기록: 2/5가 이틀 연속</li></ul>
    <p class="ai-label">한계</p>
    <p class="ai-limit">수면·컨디션 기록만으로 판단했습니다.</p>
  </details>
  <p class="ai-expert"><span aria-hidden="true">ⓘ</span> 전문가 확인 권장: 통증이나 어지럼이 있으면 운동 전에 전문가와 상의하세요.</p>
  <button type="button" class="btn-secondary">다른 안 보기</button>
</article>
```

```css
.ai-card { border:2px solid #2F6B4F; border-radius:12px; padding:20px; background:#FFFFFF; }
.ai-tag { display:inline-block; font-size:13px; font-weight:600; border:1px solid currentColor; border-radius:999px; padding:2px 10px; }
.ai-label { font-size:13px; font-weight:600; margin:8px 0 2px; }
.ai-limit { font-size:13px; color:#5C6166; border-top:1px dashed #E2E3DF; padding-top:8px; }
.ai-expert { font-size:13px; border:1px solid #1D1F21; border-radius:8px; padding:8px 12px; }
```

- 근거·한계는 한 줄만 보이다가 "근거 자세히"를 누르면 펼쳐진다.
- 전문가 확인 권장은 통증·어지럼처럼 필요한 경우에만 둔다.

### 기록 입력

- 빠른 입력이 기본: 한 줄 입력칸 + 최근 기록 칩 3개("어제와 같게", "지난 세션 반복").
- 정밀 입력은 "자세히" 버튼으로 펼친다. 처음부터 모든 칸을 보여 주지 않는다.
- 저장에 실패하면 입력 내용을 지우지 않고, 입력칸 아래에 "저장하지 못했어요 · 다시 저장하기"를 띄운다.

### 추이 차트

- 선 그래프 하나에 지표 하나. 여러 지표를 겹치지 않는다.
- 기록이 빠진 날은 선을 끊고, 끊긴 구간 아래에 "기록 없음" 라벨을 단다.
- 측정 조건이 다른 값은 속이 빈 점(○)으로 표시하고 범례에 "비표준 측정"이라고 적는다.

### 모달

- 최대 너비 640px, 배경은 반투명 어둡게. 안쪽 항목은 작은 카드로 나눈다.
- 닫기 버튼 · Esc 키 · 바깥 누르기로 닫힌다.

### 상태 표현

| 상태 | 표현 |
|---|---|
| 빈 상태 | 문장 한 줄 + 버튼 하나. "이번 주 기록이 아직 없어요. 오늘 컨디션부터 남겨 볼까요?" |
| 로딩 | 카드 자리에 같은 크기의 회색 상자 + 무엇을 하는 중인지 한 줄 |
| 오류 | 주의 색 테두리 + ⚠ 기호 + 원인 한 줄 + 다시 하기 버튼 |
| 이상치 | 값 옆에 "확인 필요" 칩 + 측정 조건을 묻는 한 줄 |

### 이미지

- 운동 동작 이미지는 4:3 비율로 자르고, 이미지 아래에 동작 이름을 글자로 쓴다.

## 7. 문구 톤

- 존댓말, 짧게. 한 문장에 한 가지만 말한다.
- 사용자를 탓하지 않는다. "실패", "미달성" 대신 "오늘은 쉬어 갔어요"처럼 사실만 말한다.
- 버튼은 무엇이 일어나는지 동사로 쓴다. "확인" 대신 "기록 저장하기".
- 화면 이름과 버튼 이름은 `service-structure.md`의 "화면에 쓸 말"을 그대로 쓴다.

## 8. 하지 말 것

- 색만으로 상태·위계·변화를 구분하지 않는다. 기호와 낱말을 함께 쓴다.
- 체중 증가나 기록 감소를 빨간 경고로 강조하지 않는다.
- 기록이 빠진 날을 "실패"처럼 보이게 하지 않는다.
- 화면당 주요 버튼을 2개 이상 두지 않는다.
- `data` 폴더에 없는 수치·그래프·점수·사람 사진을 만들어 넣지 않는다.
- AI 판단을 근거 없이 단정하는 문장으로 쓰지 않는다.
- 위 2번에 없는 색을 쓰지 않는다.
- 화면 목록·메뉴·고정 영역(예: 모든 화면에 고정된 입력창)을 이 문서를 이유로 새로 만들지 않는다. 화면 구조는 `screen-flow.md`를 따른다.
