# Claude Code 프로토타이핑 따라 하기

교재: 3.6절 Claude Code로 테마별 첫 프로토타입 만들기 (3.7절 신뢰 요소까지) · 쓰는 곳: 작업 폴더 `axyourbody-prototype` · 워크시트 문서의 「테마별로 만든 첫 프로토타입과 버전 기록」 · 지시문: [지시문 킷](../kits/claude-code-prompts.md)

## 이 가이드에서 볼 것

Claude Code로 테마별 첫 프로토타입을 만드는 하루치 실습을 **지시 → 결과 → 확인 → 수정** 순서로 한 단계씩 따라갑니다. 단계마다 "이렇게 나오면 정상"인 모습, 결과가 다를 때 다시 지시하는 문장, 망가졌을 때 되돌리는 방법이 있습니다.

- 앱 설치, 로그인, 작업 폴더 열기, 허락 요청 화면 읽기 같은 **조작**은 [「Claude Code 데스크톱 앱 설치 (Mac판 · Windows판)」](claude-code-install-guide.md)와 부록 A-5를 봅니다.
- 지시문 전문은 지시문 킷에, 김도현 프로필로 실습한 예는 교재 3.6에 있습니다. 여기서는 되풀이하지 않습니다.
- 이 실습은 기관에서 받은 Claude Pro 계정으로 Claude 데스크톱 앱의 **Code** 탭에서 합니다. 사용량 한도가 다 되었을 때는 맨 아래 「다른 도구를 쓸 때 달라지는 점」을 봅니다.

## 전체 흐름

| 단계 | 쓰는 지시문 | 만들어지는 파일 |
|---|---|---|
| 0 · 준비물 확인 | (확인 질문 한 줄) | 없음 |
| 1 · 첫 프로토타입 | 서비스 구조를 넘기고 첫 프로토타입을 만드는 지시문 | `prototype-first-<테마이름>.html` |
| 2 · 확인 | (브라우저로 열어 눌러 보기) | 없음 |
| 3 · 수정 | 수정 지시 (한 번에 한 가지) | 같은 파일이 고쳐짐 |
| 4 · 두 번째 테마 | 테마별 프로토타입 추가 생성 지시문 | `prototype-first-<둘째 테마이름>.html` |
| 5 · 복사본 | (상태 화면 지시문 첫 줄) | `prototype-first-<테마이름>-before-states.html` |
| 6 · 상태 화면 | 빈 상태·오류 등 상태 화면과 신뢰 요소 추가 지시문 | 같은 파일에 상태 화면이 더해짐 |
| 7 · 신뢰 요소 | 같은 지시문의 신뢰 요소 부분 (교재 3.7) | 같은 파일의 AI 판단 카드가 바뀜 |
| 8 · 버전 기록 | (워크시트 문서에 쓰기) | 버전 기록 표의 행 |

`<테마이름>`은 쇼핑 목록에 적은 테마 이름(영문 소문자와 하이픈)입니다.

## 0단계 · 준비물 확인

작업 폴더가 아래처럼 되어 있어야 합니다. 폴더 만들기와 `.md` 파일 저장 방법은 부록 A-5와 「화면 흐름 순서표 작성 가이드」의 「`context/screen-flow.md`로 옮기기」를 봅니다.

```text
axyourbody-prototype/
├── context/service-structure.md     ← Claude에 넘길 서비스 구조 설명서
├── context/screen-flow.md           ← 화면 흐름 순서표·화면 목록·상태 화면 목록
├── design/DESIGN-<테마이름>.md       ← 쇼핑 목록의 테마 2~3개
└── data/                            ← 고른 프로필의 CSV 4개
```

**지시.** Claude 데스크톱 앱의 Code 탭에서 `axyourbody-prototype` 폴더를 작업 폴더로 연 뒤 이렇게 묻습니다.

```text
작업 폴더의 파일 목록을 폴더별로 보여 주세요. 파일은 만들거나 고치지 마세요.
```

**이렇게 나오면 정상입니다.** `context`에 두 파일, `design`에 `DESIGN-`로 시작하는 파일 2~3개, `data`에 `body.csv` · `workout.csv` · `meal.csv` · `sleep.csv` 네 파일이 보입니다.

> [캡처 예정] Mac · Windows: Code 탭에서 작업 폴더를 연 상태와 파일 목록 답변

**다를 때.**

- CSV가 `data/m-general/body.csv`처럼 한 단계 안쪽에 있다 → 파일 탐색기에서 CSV 네 개를 `data` 바로 아래로 옮깁니다.
- 파일 이름 끝이 `.md.txt`이거나 `.csv`가 아니다 → 확장자 보기를 켜고 고칩니다(「디자인 쇼핑처 둘러보기 가이드」의 실수 예).
- 목록에 `axyourbody-prototype`의 바깥 파일이 보인다 → 작업 폴더를 한 단계 위로 잘못 연 것입니다. 「Claude Code 데스크톱 앱 설치」를 보고 `axyourbody-prototype` 폴더를 다시 엽니다.

## 1단계 · 첫 프로토타입 지시

**지시.** 지시문 킷의 「서비스 구조를 넘기고 첫 프로토타입을 만드는 지시문」(또는 교재 3.6 [실습 안내] 1단계)을 붙여 넣고 `{ }`를 내 테마 이름과 프로필로 바꿉니다. 첫 테마는 시안 비교표의 한 줄 결론에서 고른 테마입니다. `@`를 치면 파일 이름 후보가 뜨므로 골라서 넣으면 오타가 없습니다.

**결과 ① 요약과 질문.** 지시문 끝에 요약과 질문을 먼저 해 달라고 했으므로, Claude Code는 바로 만들지 않고 **이해한 내용 다섯 줄과 질문**을 돌려줍니다.

**확인.** 요약에 아래가 들어 있는지 봅니다.

- [ ] 사용자가 내 프로필이다
- [ ] 만들 화면 수가 `screen-flow.md` 화면 목록의 수와 같다
- [ ] 디자인 파일이 `DESIGN-<테마이름>.md`이고, 결과 파일 이름이 `prototype-first-<테마이름>.html`이다
- [ ] 수치를 `data` 폴더에서 가져온다고 했다

질문에는 하나씩 짧게 답하고, 요약이 맞으면 "좋습니다. 이대로 만들어 주세요."라고 보냅니다.

> [캡처 예정] 공통: 요약 다섯 줄과 질문이 돌아온 화면 (가상 프로필 데이터)

**결과 ② 파일 만들기.** 파일을 만들기 전에 허락을 묻는 창이 뜹니다. 만들 파일 이름이 `prototype-first-<테마이름>.html`이고 작업 폴더 안이면 허락합니다. 몇 분 뒤 "만든 화면 목록"과 "아직 만들지 않은 화면 목록"을 알려 줍니다.

**이렇게 나오면 정상입니다.** 작업 폴더 맨 위에 `prototype-first-<테마이름>.html`이 생기고, 아직 만들지 않은 화면이 없거나 이유와 함께 적혀 있습니다.

**다를 때 다시 지시하는 문장.**

- 요약 없이 바로 만들기 시작했다 → 멈추고 "만들기 전에 이해한 내용을 다섯 줄로 요약해 주세요. 제가 확인한 뒤에 시작합니다."
- 요약의 화면 수가 다르다 → "screen-flow.md의 '화면 목록' 표에 있는 화면만 만듭니다. 그 표의 화면 이름을 순서대로 다시 읽어 주세요."
- 파일 이름이 다르다 → "방금 만든 파일 이름을 prototype-first-<테마이름>.html로 바꿔 주세요. 내용은 바꾸지 마세요."
- 빠진 화면이 있다 → "아직 만들지 않은 {화면 이름}을 같은 파일에 만들고, {앞 화면}의 {버튼 이름} 버튼과 이어 주세요. 다른 화면은 바꾸지 마세요."

## 2단계 · 브라우저로 열어 확인

**열기.** 파일 탐색기에서 `prototype-first-<테마이름>.html`을 더블클릭합니다. 브라우저 대신 편집기가 열리면 오른쪽 버튼 → 다음으로 열기(Mac) 또는 연결 프로그램(Windows)에서 Chrome, Safari, Edge 같은 브라우저를 고릅니다.

> [캡처 예정] Mac · Windows: 첫 프로토타입을 브라우저로 연 첫 화면 (가상 프로필 데이터)

**확인 목록 네 가지**(교재 3.6 「확인」)를 이렇게 점검합니다. 발견한 문제는 고치기 전에 번호를 붙여 메모장에 먼저 모아 둡니다.

| 확인할 것 | 점검하는 방법 |
|---|---|
| 흐름대로 끝까지 눌러지는가 | `screen-flow.md`의 기본 흐름을 옆에 띄우고, 첫 화면부터 화살표 하나에 버튼 하나씩 눌러 갑니다. 갈림길도 한 번씩 따라갑니다. 막다른 화면, 아무 일도 없는 버튼을 적습니다 |
| 이름이 용어 대조표와 같은가 | 브라우저에서 `Cmd+F`(Windows `Ctrl+F`)를 누르고 서비스 구조 설명서의 **피할 말**을 하나씩 찾습니다. 하나도 찾아지지 않으면 정상입니다 |
| 숫자가 CSV 값과 같은가 | 화면의 숫자 세 개를 골라 CSV에서 같은 날짜 줄을 찾아 맞춰 봅니다. 출처를 모르는 숫자가 있으면 Claude Code에 "화면의 수치마다 어느 CSV의 어느 날짜 값인지 표로 보여 주세요. 파일은 고치지 마세요."라고 묻고, 표에 없는 숫자를 지어낸 수치로 적습니다 |
| 모바일 폭에서도 쓸 만한가 | 브라우저 창을 휴대폰 너비만큼 좁힙니다. 더 정확히 보려면 개발자 도구(`Cmd+Option+I` / `F12`)의 기기 모드(`Cmd+Shift+M` / `Ctrl+Shift+M`)를 씁니다. 글자가 잘리거나 가로로 밀리는 곳을 적습니다 |

## 3단계 · 한 번에 한 가지씩 수정

메모한 문제 중 **과업을 막는 것**(흐름이 끊김, 지어낸 수치)부터 하나씩 고칩니다. 수정 지시에는 네 가지를 넣습니다. 좋은 예와 아쉬운 예는 교재 3.6 표에 있습니다.

```text
{화면 이름}의 {영역}이 지금 {현재 모습}입니다.
{바뀌어야 할 모습}으로 바꿔 주세요.
{바꾸지 말아야 할 것}은 바꾸지 마세요.
```

**결과.** Claude Code가 고친 곳을 짧게 알려 줍니다. 브라우저로 돌아가 **새로고침**(`Cmd+R` / `F5`)한 뒤 확인합니다. 새로고침을 하지 않으면 고치기 전 화면이 그대로 보입니다.

**이렇게 나오면 정상입니다.** 지시한 곳만 바뀌고, 앞에서 통과한 확인 항목은 여전히 통과합니다.

**자주 나오는 결과와 다시 지시하는 문장.**

| 이렇게 나왔다 | 다시 지시하는 문장 |
|---|---|
| 버튼을 눌러도 아무 일이 없다 | {화면 이름}의 "{버튼 이름}" 버튼을 누르면 {다음 화면}으로 가야 하는데 아무 일도 없습니다. 이 버튼만 이어 주세요. |
| 피할 말이 화면에 나왔다 | 화면 전체에서 "{피할 말}"을 service-structure.md의 "화면에 쓸 말"인 "{쓸 말}"로 바꿔 주세요. 다른 문구는 바꾸지 마세요. |
| 지어낸 수치가 있다 | {화면 이름}의 {숫자}는 data 폴더에 없는 값입니다. CSV에 있는 값으로 바꾸거나, 없으면 그 칸을 지워 주세요. |
| 고쳤더니 다른 곳도 바뀌었다 | 방금 수정에서 {바뀐 곳}도 바뀌었습니다. 그 부분만 수정 전으로 되돌려 주세요. |
| 모바일 폭에서 표가 넘친다 | 창 너비가 좁을 때 {화면 이름}의 표가 화면 밖으로 넘칩니다. 좁은 폭에서는 표를 카드 목록으로 바꿔 보여 주세요. 데스크톱 화면은 바꾸지 마세요. |

- 테마마다 수정은 **두세 번**이면 충분합니다. 남은 문제는 버전 기록의 "다음에 할 일"에 적고 넘어갑니다. 이상한 값처럼 상태 화면에서 다룰 문제는 6단계로 미룹니다.
- 결과가 계속 어긋나면 고치기 전에 "무엇을 바꿀지 목록으로 먼저 보여 주고, 제가 승인하면 고쳐 주세요."를 붙입니다. 되묻는 문장은 교재 3.6 「막힐 때 되묻는 법」에 더 있습니다.

## 4단계 · 두 번째 테마 만들기

**지시.** 「테마별 프로토타입 추가 생성 지시문」의 `{ }`에 첫 테마와 둘째 테마 이름을 넣어 보냅니다.

**이렇게 나오면 정상입니다.**

- [ ] 작업 폴더에 `prototype-first-<둘째 테마이름>.html`이 새로 생겼다
- [ ] 첫 테마 파일을 다시 열어 보면 그대로다
- [ ] Claude Code가 알려 준 차이가 **디자인(색·글꼴·모양·간격)뿐**이다
- [ ] 두 파일을 브라우저 탭 두 개에 열고 같은 화면을 오가 보면 화면 이름·버튼 문구·숫자가 같다

> [캡처 예정] 공통: 두 테마 파일을 브라우저 탭 두 개로 열어 같은 화면을 비교한 모습 (가상 프로필 데이터)

**다를 때.**

- 화면 구성이나 문구가 달라졌다 → "prototype-first-<둘째 테마이름>.html에서 {달라진 곳}이 첫 테마 파일과 다릅니다. 첫 테마 파일과 같게 맞추고 디자인만 DESIGN-<둘째 테마이름>.md를 따르게 해 주세요."
- 첫 테마 파일이 바뀌었다 → 5단계의 되돌리기 방법으로 돌려놓고, 지시문의 "고치지 마" 줄이 들어 있었는지 확인합니다.

세 번째 DESIGN.md가 있으면 같은 지시로 하나 더 만듭니다. 시간이 모자라면 두 테마로 6단계까지 먼저 마칩니다.

## 5단계 · 큰 변경 전에 복사본 만들기

상태 화면을 더하는 일은 파일을 크게 바꿉니다. 그 전에 지금 파일을 다른 이름으로 복사해 둡니다. 이름은 원래 이름 뒤에 `-before-states`를 붙인 `prototype-first-<테마이름>-before-states.html`입니다. 6단계의 지시문 첫 줄이 이 복사를 시키므로 따로 하지 않아도 되지만, 직접 해 두면 더 확실합니다.

- Mac: Finder에서 파일을 고르고 `Cmd+D`(복제) → 생긴 사본의 이름을 고칩니다.
- Windows: 파일 탐색기에서 `Ctrl+C`, `Ctrl+V` → "- 복사본"이 붙은 파일의 이름을 `F2`로 고칩니다.

**이렇게 나오면 정상입니다.** 두 파일이 나란히 있고, 복사본을 브라우저로 열면 지금까지 만든 화면이 그대로 열립니다.

> [캡처 예정] Mac · Windows: 원본과 `-before-states` 복사본이 나란히 있는 작업 폴더

다른 큰 변경(예: 화면 배치를 통째로 바꾸기) 전에도 같은 방법으로 `-before-` 뒤에 바꾸려는 일을 붙인 복사본을 둡니다.

**되돌리기.** 고친 파일이 망가졌으면 이렇게 지시합니다.

```text
prototype-first-<테마이름>.html을 prototype-first-<테마이름>-before-states.html과 똑같은 내용으로 되돌려 주세요. 복사본 파일은 그대로 두세요.
```

직접 되돌릴 때는 망가진 파일을 지우고, 복사본을 한 번 더 복사해 원래 이름으로 바꿉니다. 복사본 자체는 늘 남겨 둡니다.

## 6단계 · 상태 화면 더하기

**지시.** 「빈 상태·오류 등 상태 화면과 신뢰 요소 추가 지시문」의 상태 화면 부분을 보냅니다. `{ }` 네 줄은 **내 `screen-flow.md`의 상태 화면 목록**에서 옮겨 씁니다. 교재 3.6 예시의 날짜와 값은 김도현 프로필의 것이므로 내 프로필에는 내 목록의 근거 데이터를 씁니다.

**결과.** 복사본이 먼저 만들어지고, 상태 화면이 더해진 뒤 다른 테마 파일에도 같은 작업이 이어집니다. 허락 창이 여러 번 뜰 수 있습니다. 파일 이름이 작업 폴더 안의 `prototype-first-`로 시작하는 파일이면 허락합니다.

**확인 — 이렇게 나오면 정상입니다.** "상태 미리 보기" 전환 버튼을 하나씩 눌러 봅니다.

- [ ] 정상 · 빈 상태 · 오류 · 로딩 · 이상치를 모두 바꿔 볼 수 있다
- [ ] 빈 상태에 탓하는 말이 없고, 다음 행동 버튼이 하나 있다
- [ ] 오류 상태에서 입력해 둔 내용이 지워지지 않고, 원인과 다시 하기 버튼이 보인다
- [ ] 로딩 상태에 무엇을 하는 중인지 글로 보인다
- [ ] 이상치가 빨간 경고만이 아니라 글로 된 안내와 선택(예: 다른 기준으로 보기)으로 나온다
- [ ] 상태마다 색 말고도 라벨이나 아이콘으로 구분된다

> [캡처 예정] 공통: 상태 미리 보기 버튼과 빈 상태 · 이상치 화면 (가상 프로필 데이터)

**다를 때.**

- 상태 미리 보기 버튼이 없다 → "화면에 상태 미리 보기 전환 버튼을 달아, 정상·빈 상태·오류·로딩·이상치를 바꿔 가며 볼 수 있게 해 주세요. 다른 부분은 바꾸지 마세요."
- 한 상태만 빠졌다 → "상태 미리 보기에서 {상태}를 눌러도 화면이 바뀌지 않습니다. screen-flow.md 상태 화면 목록의 {상태} 줄대로 만들어 주세요."
- 다른 테마 파일에는 반영되지 않았다 → "prototype-first-<다른 테마이름>.html에도 방금과 같은 상태 화면을 추가해 주세요. 작업 전에 같은 방식으로 -before-states 복사본을 만들어 주세요."

## 7단계 · AI 판단 카드에 신뢰 요소 넣기

교재 3.7 [실습 안내]의 지시를 보냅니다. 판단 · 근거 · 한계 · 전문가 확인 권장 · 사용자의 선택이 제대로 나왔는지 보는 법과 좋은 예·고칠 예는 「AI 판단 화면 신뢰 설계 예시 모음」에 있습니다. 확인할 때는 "근거 자세히"를 눌러 펼쳐지는지, 흑백으로 봐도 라벨이 구분되는지 함께 봅니다(흑백 보기 방법은 「Stitch 시안 만들기 가이드」 4단계).

## 8단계 · 버전 기록에 한 줄씩

파일 하나를 만들거나 크게 고칠 때마다 워크시트 문서의 「테마별로 만든 첫 프로토타입과 버전 기록」에 적습니다. 칸 설명과 작성 예시는 교재 3.6 [실습 안내] 표입니다.

- **파일 경로**는 작업 폴더 이름부터 씁니다. 복사본(`-before-states`)은 행을 따로 만들지 않고 관찰 메모에 "복사본 있음"이라고 적습니다.
- **만든 때** 칸에는 쓴 지시문 이름과 수정 횟수를 화살표로 잇습니다.
- **바뀐 점·관찰 메모**에는 눌러 보며 본 사실을 좋은 점 하나, 문제 하나 이상 적습니다. "괜찮음"만 쓰지 않습니다.
- **다음에 할 일**에는 3단계에서 미룬 문제와, 다른 테마에서 가져오고 싶은 부분을 적습니다. Day 4 통합의 재료가 됩니다.

완료 기준 체크리스트 확인 방법:

- [ ] **테마별 첫 프로토타입을 2개 이상 만들었다** → 작업 폴더에 `prototype-first-`로 시작하고 `-before-`가 없는 파일이 2개 이상인지 셉니다.
- [ ] **상태 화면(빈·오류·로딩·이상치)과 신뢰 요소가 첫 프로토타입에 들어 있다** → 테마 파일마다 상태 미리 보기 다섯 가지를 눌러 보고, AI 판단 카드에 "근거"와 "한계" 라벨이 있는지 봅니다.
- [ ] **버전마다 다른 파일 이름으로 저장했다** → 버전 기록의 파일 경로 칸에 같은 경로가 두 번 나오지 않는지 봅니다.
- [ ] **버전마다 바뀐 점과 다음에 할 일을 적었다** → 행마다 두 칸이 비어 있지 않은지 봅니다. (외부 요소 출처 항목은 Day 4에 확인합니다.)

## 막혔을 때

| 증상 | 할 일 |
|---|---|
| 지시와 다른 결과가 나온다 | 원하는 결과를 한 문장으로 다시 쓰고 "무엇을 바꿀지 목록으로 먼저 보여 주고, 제가 승인하면 고쳐 주세요."를 붙입니다(부록 A-5) |
| 브라우저 화면이 하얗거나 모든 버튼이 안 된다 | "브라우저로 열면 화면이 비어 있습니다. 원인을 찾아 쉬운 말로 설명하고, 그 부분만 고쳐 주세요." 두 번 해도 안 되면 5단계 방법으로 복사본에서 되돌립니다 |
| 고쳤다는데 화면이 그대로다 | 새로고침(`Cmd+R` / `F5`)합니다. 그래도 같으면 브라우저 주소창 끝의 파일 이름이 지금 고친 파일인지 봅니다 |
| 작업 폴더 밖의 파일을 고치거나 무엇을 설치하겠다고 한다 | 허락하지 않고 "왜 필요한지 먼저 설명해 주세요. 작업 폴더 안에서, 외부 라이브러리 없이 할 수 있는 방법으로 해 주세요."라고 답합니다 |
| `@`로 가리킨 파일을 못 찾는다 | 작업 폴더를 잘못 연 것입니다. 0단계 확인 질문으로 파일 목록을 다시 봅니다 |
| 대화가 길어져 앞에서 정한 것을 잊는다 | 새 대화를 열고 "@context/service-structure.md @context/screen-flow.md 와 prototype-first-<테마이름>.html을 먼저 읽고, 지금 파일의 화면 목록을 알려 주세요."로 시작합니다. 재료와 결과가 파일에 있으므로 이어서 할 수 있습니다 |
| 사용량 한도 안내가 나왔다 | 만든 파일은 작업 폴더에 그대로 남습니다. 안내된 다시 쓸 수 있는 시각까지 브라우저 확인과 버전 기록을 먼저 합니다. 기다릴 수 없으면 아래 「다른 도구를 쓸 때 달라지는 점」을 봅니다 |

## 다른 도구를 쓸 때 달라지는 점

Claude Pro의 사용량 한도가 다 되었을 때는 아래 세 가지가 되는 다른 AI 코딩 도구를 써도 됩니다. 예) OpenAI Codex, Cursor.

1. 내 컴퓨터의 폴더를 작업 폴더로 연다
2. 그 폴더 안의 파일을 읽고, 만들고, 고친다
3. 대화창에서 글로 지시한다

설치와 로그인은 「Claude Code 데스크톱 앱 설치 (Mac판 · Windows판)」의 다른 도구 안내를 봅니다.

**그대로인 것.** 작업 폴더와 파일 이름, 지시문 킷의 지시문, 지시 → 결과 → 확인 → 수정 순서, 복사본 만들기, 버전 기록.

**달라지는 것.**

| 달라지는 것 | 이렇게 맞춥니다 |
|---|---|
| 파일을 가리키는 방법 | `@`로 파일이 골라지지 않으면 "context 폴더의 service-structure.md 파일"처럼 경로를 글로 씁니다 |
| 허락을 묻는 방식과 모드 | 도구마다 파일 수정 전에 묻는 방식이 다릅니다. 처음에는 **수정 전에 묻는 쪽**으로 두고, 작업 폴더 밖 수정이나 설치는 똑같이 거절합니다 |
| 앞 대화를 모른다 | 첫 지시로 "context 폴더의 두 파일과 작업 폴더의 prototype-first-로 시작하는 파일을 먼저 읽고, 이해한 내용을 다섯 줄로 요약해 주세요. 파일은 아직 고치지 마세요."를 보냅니다. 요약을 확인한 뒤 하던 단계부터 이어 갑니다 |
| 결과 파일이 다른 곳에 생긴다 | 새 폴더(예: `src`)를 만들려 하면 "작업 폴더 맨 위에 prototype-first-<테마이름>.html 한 파일로 만들어 주세요."라고 다시 지시합니다 |
| 외부 라이브러리를 쓰려 한다 | "외부 라이브러리 없이 HTML·CSS와 간단한 JavaScript만으로, 더블클릭하면 열리게 해 주세요."라고 지시합니다 |

버전 기록의 관찰 메모에 어느 단계부터 어떤 도구를 썼는지 한 줄 적어 둡니다. 다음 단계는 Day 4의 「여러 버전 통합 가이드」로 이어집니다.
