# 나만의 DESIGN.md 만들기 가이드

교재: 4.6절 나만의 DESIGN.md 만들기 · 지시문: 지시문 킷의 「테마 일체감 통합 지시문」 → 「나만의 DESIGN.md 명세 추출 지시문」 → 「나만의 DESIGN.md 단독 문서 보강 지시문」 · 만드는 파일: `prototype-final.html`, `my-own-DESIGN.md`, 재현 시험용 `reproduction-test.html` · 쓰는 곳: 워크시트 문서 「나만의 디자인 가이드(DESIGN.md)와 점검표」, 버전 기록의 최종 프로토타입 · 나만의 DESIGN.md 행

## 이 가이드에서 볼 것

- 세 지시를 순서대로, **한 번에 하나씩** 보냅니다. 결과를 확인하고 나서 다음 지시로 넘어갑니다.
- 완성한 문서는 작업 폴더 **바깥의 빈 폴더**에서 새 대화로 재현 시험을 합니다.
- 점검표 여섯 항목은 "찾아보기"로 확인합니다. 아래에 항목별 확인 방법이 있습니다.

세 단계가 왜 필요한지, 명세에 담을 다섯 가지, 점검표 작성 예시는 교재 4.6절에 있습니다. Code 탭 기본 조작은 「[Claude Code 프로토타이핑 따라 하기](claude-code-prototyping-guide.md)」와 부록 A-5를 봅니다.

## 시작 전에

- [ ] 4.5절에서 고른 기본 색 값과 `favicon.svg`가 버전 기록과 작업 폴더에 있다.
- [ ] 테마 통일의 기준이 될 `design/DESIGN-<테마이름>.md` 하나를 정했다(고르는 기준은 교재 4.6절 1단계).
- [ ] 킷 기본형과 교재 예시가 조금 다르다는 것을 알았다. 킷의 테마 일체감 통합 지시문에 교재 예시의 두 줄 "같은 역할의 영역은 같은 모양으로 맞춰(판단 카드끼리, 기록 카드끼리, 수치 카드끼리)", "흑백 보기에서 고친 라벨·기호·무늬는 지우지 마"를 더해 씁니다.

## 1단계 · 테마 일체감 통합 → `prototype-final.html`

킷 기본형은 바꾸기 전에 "영역별로 어긋난 부분 목록"을 먼저 보여 줍니다. 목록을 읽고 빠진 곳이 있으면 더한 뒤 "좋아, 이 목록대로 고쳐 줘"라고 승인합니다.

**이렇게 나오면 정상**
- `prototype-final.html`이 새로 생기고 `prototype-improved.html`은 그대로입니다.
- 두 파일을 브라우저 두 창에 나란히 열면 배치·문구·영역 순서는 같고, 색·글꼴·모서리·그림자·간격만 하나로 맞춰져 있습니다.
- 강조색은 고른 색 하나만 보이고, 판단 카드는 판단 카드끼리 같은 모양입니다.
- 흑백 보기를 켜도 4.5절에서 더한 라벨·기호·무늬가 그대로 있고, 탭에 파비콘이 보입니다.

**다르게 나오면 이렇게 다시 지시합니다**
- 배치가 바뀌었다 → "배치와 영역 순서가 prototype-improved.html 과 달라졌어. 배치는 원래대로 두고 색·글꼴·모서리·그림자·간격만 바꿔 줘."
- 강조색이 여러 개 남았다 → "prototype-final.html 에서 {고른 색 값} 말고 강조색으로 쓰인 색을 줄 번호와 함께 보여 주고, 내가 승인하면 모두 {고른 색 값}으로 바꿔 줘."
- 라벨이 사라졌다 → "흑백 보기용으로 넣은 '{라벨}'이 사라졌어. 원래 자리에 다시 넣어 줘."
- 같은 역할인데 모양이 다르다 → "{영역 A}와 {영역 B}는 둘 다 기록 카드야. 같은 모양으로 맞춰 줘."

## 2단계 · 명세 추출 → `my-own-DESIGN.md` 초안

**이렇게 나오면 정상**
- `my-own-DESIGN.md`가 생기고, 다섯 가지 내용이 제목으로 나뉘어 있습니다. 확인은 "my-own-DESIGN.md 의 제목(# 으로 시작하는 줄)만 순서대로 보여 줘"로 합니다.
- 글꼴 크기·그리드·여백이 px, 칸 수 같은 숫자로 적혀 있습니다.
- 다른 파일 이름이 섞여 있어도 **이 단계에서는 정상**입니다. 3단계에서 풀어 씁니다.

**다르게 나오면 이렇게 다시 지시합니다**
- 색 목록과 글꼴 이름뿐이다 → "2번 설정값을 숫자로 자세히 써 줘: 용도별 글꼴 크기·굵기·줄 간격, 그리드 칸 수·최대 폭·칸 사이, 카드 안쪽 여백."
- 다섯 가지 중 빠진 것이 있다 → "{번호}번 '{내용}'이 없어. prototype-final.html 을 보고 채워 줘."
- 실제 화면과 다르다 → "my-own-DESIGN.md 의 {항목}은 {값}인데 prototype-final.html 에서는 {다른 값}이야. 실제 파일 기준으로 고쳐 줘."

3단계 전에 복사본을 만들게 합니다: "my-own-DESIGN.md 를 my-own-DESIGN-before-standalone.md 로 복사해 둬." 복사본은 워크시트 저장소에 올리지 않습니다.

## 3단계 · 단독 문서로 보강

**이렇게 나오면 정상**
- 다른 파일 이름, `DESIGN-`, 스킬 이름, "앞에서" 같은 작업 이력 표현이 없습니다(아래 점검표 확인 방법으로 찾습니다).
- 판단 카드 · 수치 카드 · 기록 카드 · 모달 · 차트마다 HTML 예제와 CSS 예제가 코드 상자로 함께 있습니다.
- 색 없이도 읽히게 하는 방침이 한 절로 있습니다.

## 4단계 · 재현 시험

1. 작업 폴더 **바깥**에 빈 새 폴더를 만듭니다(예: 바탕화면의 `design-test`). 작업 폴더 안에서 시험하면 Claude Code가 `prototype-final.html`을 찾아 참고할 수 있어 시험이 되지 않습니다.
2. `my-own-DESIGN.md`를 그 폴더로 **복사**합니다(옮기지 않습니다).
3. Code 탭에서 새 대화를 열고, 프로젝트 폴더로 `design-test`를 고릅니다.
4. "@my-own-DESIGN.md 만 기준으로 기록 캘린더 화면을 reproduction-test.html 로 만들어 줘. 값은 가상의 예시로 채우고, 이 폴더 밖의 파일은 찾지 마."라고 지시합니다.
5. `reproduction-test.html`과 `prototype-final.html`을 나란히 열어 색 · 글꼴 크기 · 카드 모양 · 상태 라벨 모양 · 여백이 같은 서비스처럼 보이는지 봅니다. 결과는 예 / 부분 / 아니오로 적습니다.
6. 화면을 캡처합니다(Mac `Cmd+Shift+4`, Windows `Win+Shift+S`). 파일 이름은 영문 소문자로, 예) `reproduction-test.png`.
7. (가능하면) Stitch에서도 시험합니다. 킷의 「Stitch 테마별 시안 생성 지시문」 [디자인 규칙] 자리에 `my-own-DESIGN.md` 내용을 붙여 넣습니다. 조작은 부록 A-4와 「[Stitch 시안 만들기 가이드](stitch-draft-guide.md)」를 봅니다.

**"부분"일 때 고치는 예** (도서관 앱 예): 재현한 대출 기록 화면에서 "반납 예정" 배지가 점선 라벨이 아니라 색 동그라미로 나왔습니다. 문서에 배지 유형이 없었기 때문입니다. 작업 폴더의 대화로 돌아가 이렇게 고쳤습니다: "재현 시험에서 기한 배지가 색 동그라미로 나왔어. my-own-DESIGN.md 의 콘텐츠 유형별 표현에 '기한 배지' 유형을 더하고 HTML·CSS 예제를 넣어 줘. 다른 파일 이름은 언급하지 마." 고친 파일을 시험 폴더에 다시 복사(덮어쓰기)하고, **새 대화**에서 다시 시험합니다.

## 점검표 여섯 항목 확인 방법

`my-own-DESIGN.md`를 텍스트 편집기(Mac)나 메모장(Windows)으로 열어 찾기(`Cmd+F`, `Ctrl+F`)를 쓰거나, Claude Code에 "고치지 마"를 붙여 물어 확인합니다.

- [ ] **다섯 가지 항목이 모두 있다** → 제목만 보여 달라고 해서 교재 4.6절 표의 1~5번과 하나씩 맞춰 봅니다.
- [ ] **설정값이 숫자로 적혀 있다** → "px"와 "칸"을 찾습니다. "넉넉하게", "적당히" 같은 말이 보이면 숫자로 바꾸게 합니다.
- [ ] **다른 파일·이력 언급이 없다** → 교재의 검색어에 ".html", "참고", "위에서"를 더해 찾습니다. 예) "my-own-DESIGN.md 에서 'prototype', 'DESIGN-', '.html', '스킬', '앞에서'가 들어간 줄을 줄 번호와 함께 보여 줘. 고치지 마."
- [ ] **HTML·CSS 예제가 영역 유형마다 있다** → 유형 이름마다 그 아래에 HTML 코드 상자와 CSS 코드 상자가 둘 다 있는지 봅니다.
- [ ] **색 없이도 읽히는 규칙이 있다** → "흑백", "라벨", "기호", "무늬"를 찾습니다.
- [ ] **재현 시험을 통과했다** → 결과 칸에 예 / 부분 / 아니오, "고칠 점"에 다르게 나온 요소와 더한 유형을 적습니다.

## 샘플과 비교하기

형식이 막막하면 자료실의 샘플 「[DESIGN-axyourbody-sample.md](../kits/DESIGN-axyourbody-sample.md)」와 나란히 놓고 봅니다. 비교할 것은 **구성**입니다: 색을 역할별 표로 정리했는가, 글꼴 크기를 용도별 표로 정리했는가, 상태 화면·모달·흑백 규칙이 각각 절로 있는가. 샘플의 값은 베끼지 않고, 값은 반드시 내 `prototype-final.html`에서 가져옵니다.

## 올리기와 버전 기록

1. 워크시트 저장소에 Add file → Upload files로 `my-own-DESIGN.md`와 재현 시험 캡처를 올리고, 점검표 아래 "재현 시험 화면" 줄에 `![재현 시험 화면](reproduction-test.png)`처럼 연결합니다(부록 A-2, 「[GitHub 워크시트 저장소 가이드](github-worksheet-repo-guide.md)」).
2. 버전 기록에 두 행을 채웁니다. 최종 프로토타입 행의 "사용 DESIGN.md"에는 기준으로 쓴 DESIGN.md 이름을, 나만의 DESIGN.md 행의 "바뀐 점·관찰 메모"에는 재현 시험 결과와 더한 유형을 적습니다.

## 자주 하는 실수와 고친 예

- **다른 파일에 기대는 문장** (도서관 앱 예: "자세한 색은 기존 스타일 파일 참고") → 색 값을 역할별 표로 풀어 씁니다.
- **화면 위치로 쓴 규칙** (배달앱 예: "두 번째 영역은 굵은 테두리") → 역할 이름으로: "주문 상태 카드는 굵은 테두리".
- **숫자 없는 말** (택배 앱 예: "여백은 넉넉하게") → "카드 안쪽 16px, 카드 사이 24px".
- **재현 시험을 작업 폴더 안에서 했다** → 통과처럼 보여도 최종 파일을 참고했을 수 있습니다. 바깥 빈 폴더와 새 대화로 다시 합니다.

## 막혔을 때

- **테마 통일 뒤 화면이 크게 바뀌었다.** `prototype-final.html`은 새 파일이므로 지우고, 1단계를 "먼저 어긋난 부분 목록만 보여 줘"부터 다시 합니다.
- **문서를 쓰다 중간에 끊겼다.** "이어서 써 줘. 이미 쓴 부분은 고치지 마." 길면 "3번 항목만 다시 자세히 써 줘"처럼 항목별로 나눠 시킵니다.
- **보강 뒤에도 파일 이름이 남아 있다.** 찾기로 나온 줄을 붙여 넣고 "이 줄들을 다른 파일 없이 내용으로 풀어 써 줘."라고 지시합니다.
- **재현 결과가 전혀 다르다.** 시험 폴더에 다른 파일이 없었는지, 새 대화였는지, 설정값이 숫자로 적혀 있는지부터 확인합니다.
- **새 폴더를 Code 탭에서 여는 법을 모르겠다.** 「[Claude Code 프로토타이핑 따라 하기](claude-code-prototyping-guide.md)」와 부록 A-5의 작업 폴더 열기를 봅니다.
- **Stitch에 붙여 넣으니 잘린다.** 기본 설정값과 콘텐츠 유형별 표현 부분을 먼저 붙여 넣고 시안을 뽑습니다.
- **사용 한도에 걸렸다.** 사전 안내의 조건에 맞는 다른 회사의 AI 코딩 도구로 이어 합니다. 재현 시험도 그 도구에서 빈 폴더를 열고 새 대화로 하면 됩니다.
