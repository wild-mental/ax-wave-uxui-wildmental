# 여러 버전 통합 가이드

교재: 4.2절 여러 버전 조합하기 · 지시문: 지시문 킷의 「여러 테마 버전 통합 지시문」(사전 단계 · 통합 지시) · 만드는 파일: `prototype-merged.html` · 쓰는 곳: 워크시트 문서의 「테마별로 만든 첫 프로토타입과 버전 기록」(버전 기록 표 · 장점 찾기 표)

## 이 가이드에서 볼 것

- 영역 지도 받기 → 장점 찾기 표 → 통합 지시 → 남은 콘텐츠 처리. 지시는 **한 번에 하나씩** 보내고, 결과를 확인한 뒤 다음으로 넘어갑니다.
- 교재와 킷에 적힌 줄 번호는 예시입니다. 반드시 **내가 받은 영역 지도의 번호**를 씁니다.
- 첫 프로토타입 파일은 고치지 않고, 결과는 새 파일에 받습니다. 색·글꼴이 섞여 보여도 지금은 그대로 둡니다(통일은 4.6절).

지시문 전문과 장점 찾기 표 예시는 교재 4.2절 [실습 안내]와 지시문 킷에 있습니다. Code 탭 기본 조작(작업 폴더 열기, `@` 표기, 허락 요청에 답하기)은 「[Claude Code 프로토타이핑 따라 하기](claude-code-prototyping-guide.md)」와 부록 A-5를 봅니다.

## 시작 전에

- [ ] Claude 데스크톱 앱 Code 탭에서 작업 폴더 `axyourbody-prototype`을 열었다.
- [ ] 폴더 맨 위에 `prototype-first-<테마이름>.html`이 두 개 이상 있고, 브라우저에서 상태 미리 보기까지 눌러 봤다. `-before-states` 복사본은 비교 대상이 아닙니다.
- [ ] **폴더째 복사본을 만들었다.** Finder(Windows는 파일 탐색기)에서 `axyourbody-prototype` 폴더를 복사해 작업 폴더 바깥(예: 바탕화면)에 `axyourbody-prototype-day3`처럼 두면, 무엇이 잘못돼도 Day 3 끝 상태로 돌아갈 수 있습니다.
- [ ] Day 3 대화가 아주 길었다면 새 대화로 시작했다. 필요한 파일은 지시문에 이름으로 들어가므로 앞 대화가 없어도 됩니다.

## 1단계 · 영역 지도 받기 (조사만)

킷의 사전 단계 지시문에 내 파일 이름을 넣어 보냅니다. 교재 예시처럼 "영역 이름은 @context/service-structure.md 의 "화면에 쓸 말"에 있는 이름을 써 줘" 한 줄을 더하면 파일끼리 비교하기 쉬워집니다.

**이렇게 나오면 정상**
- 파일마다 표가 하나씩 나오고, 칸은 영역 이름 · 시작 줄 · 끝 줄 · 한 줄 설명입니다.
- 같은 역할의 영역은 파일이 달라도 같은 이름입니다. 줄 번호는 파일마다 다릅니다.
- 파일을 고치겠다는 허락 요청이 없습니다.

**다르게 나오면 이렇게 다시 지시합니다**
- 영역 이름이 파일마다 다르다 → "같은 역할의 영역은 모든 파일에서 같은 이름으로 맞춰 표를 다시 보여 줘. 파일은 고치지 마."
- 화면 하나가 통째로 한 영역이다 → "대시보드를 상단 메뉴, 카드 하나처럼 역할 하나 단위로 더 잘게 나눠 줘."
- 파일을 고치겠다고 허락을 묻는다 → 거절하고 "아직 아무 파일도 고치지 마. 표만 보여 줘."

받은 표는 복사해 워크시트의 장점 찾기 표 아래에 붙여 둡니다. 다음 단계에서 번호를 옮겨 적기 쉽습니다.

## 2단계 · 줄 번호 읽고 장점 찾기 표 채우기

1. 브라우저 창 두세 개에 첫 프로토타입을 하나씩 열어 나란히 놓고, 영역 하나씩 비교합니다. 기호와 근거 쓰는 법은 교재 4.2절 예제 표를 따릅니다.
2. 어떤 줄 범위가 화면의 어디인지 헷갈리면 이렇게 묻습니다: "prototype-first-<테마이름>.html 의 {시작}~{끝}줄이 화면에서 무엇인지 한 줄로 설명해 줘. 고치지 마."
3. "가져올 버전" 칸에는 파일 하나만 적습니다. "근거" 칸에는 과업·불편 목록의 번호나 페르소나 카드의 문장을 씁니다. "더 예뻐서"는 근거가 아닙니다.
4. 가장 많은 영역을 가져오는 파일을 **뼈대 기준 파일**로 정하면 옮기는 양이 줄어듭니다.

## 3단계 · 통합 지시 보내기

킷의 통합 지시를 쓰고, 번호 목록 한 줄에 장점 찾기 표 한 행을 옮깁니다. 순서는 화면 위에서 아래입니다. 킷 기본형에 없는 교재 예시의 세 줄을 "지킬 것"과 끝에 더해 씁니다.

- "수치는 data 폴더의 CSV(가상 프로필) 값만 써."
- "색과 글꼴이 섞여도 지금은 그대로 둬. 테마 통일은 나중에 따로 할 거야."
- "내가 답하기 전에는 더 고치지 마."

**버전이 두 개일 때**는 번호 목록에 파일 이름이 두 가지만 번갈아 나옵니다. 김도현 프로필 테마 이름으로 쓴 형식 예입니다.

```text
전체 뼈대는 prototype-first-neat-basic.html 을 기준으로 해.
1. {영역 이름}: prototype-first-neat-basic.html {시작}~{끝}줄
2. {영역 이름}: prototype-first-bright-coaching.html {시작}~{끝}줄
3. {영역 이름}: prototype-first-neat-basic.html {시작}~{끝}줄
```

**이렇게 나오면 정상**
- 폴더에 `prototype-merged.html`이 새로 생기고, 첫 프로토타입 파일들의 수정 시각(Finder 목록 보기의 "수정일", 파일 탐색기의 "수정한 날짜")은 그대로입니다.
- 번호 목록의 영역이 그 순서대로 보이고, 메뉴로 화면을 오갈 수 있습니다.
- 상태 미리 보기 버튼을 누르면 옮겨 온 영역에서도 빈 상태·오류·로딩·이상치가 바뀝니다.
- 영역마다 색·글꼴이 달라 보입니다. 이 단계에서는 정상입니다.
- 대화 끝에 옮기지 않은 콘텐츠 목록과 질문이 있고, Claude Code가 답을 기다립니다.

**확인하는 법:** 내가 보낸 번호 목록을 그대로 확인 목록으로 씁니다. 브라우저에서 1번부터 하나씩 찾아, 가져오라고 한 파일의 모양과 같은지 봅니다.

**다르게 나오면 이렇게 다시 지시합니다**
- 영역이 빠졌다 → "번호 목록의 {번호}번 {영역 이름}이 prototype-merged.html 에 없어. {파일} {시작}~{끝}줄에서 가져와 넣어 줘. 다른 영역은 고치지 마."
- 다른 버전의 모양으로 들어왔다 → "{번호}번은 {파일}에서 가져와야 해. 무엇을 바꿀지 먼저 목록으로 보여 주고, 내가 승인하면 고쳐 줘."
- 색을 멋대로 통일했다 → "이번 단계에서는 각 영역의 색과 글꼴을 원래 파일 그대로 둬야 해. 원래 스타일로 되돌려 줘."
- 상태 화면이 빠졌다 → "{영역 이름}의 빈 상태·오류·로딩·이상치 화면이 없어. {파일}에서 함께 옮기고 상태 미리 보기 버튼에 연결해 줘."

## 4단계 · 옮기지 않은 콘텐츠 처리하기

1. 목록의 항목마다 "내 과업에 필요한가, 서비스 구조 설명서에 있는 대상 객체·속성인가"를 보고 넣을지 버릴지 정합니다.
2. 넣기 전에 복사본을 만들게 합니다: "prototype-merged.html 을 prototype-merged-before-leftover.html 로 복사해 둬."
3. 항목 번호로 답합니다: "1번은 {영역 이름} 아래에 넣어 줘. 2번은 넣지 마. 다른 영역은 고치지 말고, 끝나면 바뀐 줄 범위를 알려 줘."
4. 목록이 비어 있다는 답이 오면 한 번 더 묻습니다: "첫 프로토타입 파일들의 화면 문구를 하나씩 비교해서, prototype-merged.html 에 없는 문장이 정말 없는지 다시 확인해 줘. 고치지 마."

## 5단계 · 통합 프로토타입의 영역 지도 다시 받기

4.3절부터는 `prototype-merged.html`의 줄 범위로 지시합니다. 1단계의 영역 지도는 첫 프로토타입의 번호이므로 그대로 쓸 수 없습니다. "prototype-merged.html 의 영역 지도를 같은 형식으로 만들어 줘. 아무 파일도 고치지 마."라고 다시 받습니다. 파일을 고칠 때마다 줄 번호가 밀리므로, **줄 번호로 지시하기 직전에는 늘 영역 지도를 새로 받습니다.**

## 6단계 · 버전 기록에 행 추가

통합 프로토타입 행을 교재 4.2절 ④의 예처럼 채웁니다. "바뀐 점·관찰 메모"에는 통합한 영역 수와 남은 콘텐츠를 어떻게 처리했는지, "다음에 할 일"에는 4.3절에서 보강할 영역 후보를 적습니다.

## 자주 하는 실수와 고친 예

- **전체로 나은 버전 하나만 남겼다** (배달앱 예: "B 시안이 전체적으로 나으니 B로") → 영역별로 고릅니다: "가게 목록은 B, 주문 상태 표시는 A".
- **뭉뚱그려 지시했다** (도서관 앱 예: "검색창이랑 대출 카드 좀 섞어 줘") → 번호 목록으로: "1. 검색창: 파일 A {시작}~{끝}줄 / 2. 대출 현황 카드: 파일 B {시작}~{끝}줄".
- **교재 예시의 줄 번호를 그대로 붙여 넣었다** → 엉뚱한 부분이 옮겨집니다. 내 영역 지도 번호로 바꿉니다.
- **통합하면서 색 통일까지 시켰다** → 배치 문제와 색 문제를 구분할 수 없게 됩니다. 색은 4.6절에서 따로 맞춥니다.
- **남은 콘텐츠 질문에 "알아서 해 줘"라고 답했다** → 넣을 곳은 기획자인 내가 정합니다. 항목마다 넣을 영역을 지정합니다.

## 막혔을 때

- **줄 번호가 어긋난다.** 영역 지도를 받은 뒤 파일이 고쳐졌을 가능성이 큽니다. 영역 지도를 다시 받거나, 줄 번호 대신 "영역 지도의 '{영역 이름}' 영역 전체"로 지정하고 결과를 그 범위로 확인합니다.
- **첫 프로토타입 파일이 바뀌었다.** "방금 prototype-first-<테마이름>.html 에 한 변경을 모두 되돌려 줘."라고 지시합니다. 되돌아오지 않으면 시작 전에 만든 폴더 복사본에서 그 파일만 다시 복사해 옵니다.
- **메뉴를 눌러도 화면이 바뀌지 않는다.** 여러 버전의 화면 이동 코드가 부딪친 경우가 많습니다. "상단 메뉴의 {메뉴 이름}을 눌러도 아무 일도 없어. 원인을 먼저 설명하고, 화면 이동 코드를 한 가지로 정리해 줘. 화면 모양은 바꾸지 마."
- **통합 파일이 빈 화면으로 열린다.** "prototype-merged.html 을 열면 {보이는 증상}. 원인을 먼저 찾아 설명하고, 내가 승인하면 고쳐 줘."
- **만들다 중간에 멈췄다.** "이어서 계속해 줘. 이미 만든 부분은 고치지 마."라고 보냅니다. 대화가 너무 길어 앞 내용을 잊는 듯하면 새 대화를 열고 5단계처럼 영역 지도부터 다시 받습니다.
- **사용 한도에 걸렸다.** 사전 안내의 조건에 맞는 다른 회사의 AI 코딩 도구(OpenAI Codex, Cursor 등)로 같은 작업 폴더를 열고 이어 합니다. 지시문은 그대로 쓰고 `@` 표기만 그 도구의 파일 지정 방식으로 바꿉니다.
- Code 탭 조작은 「[Claude Code 프로토타이핑 따라 하기](claude-code-prototyping-guide.md)」와 부록 A-5, 워크시트 저장소에 표를 붙이는 조작은 부록 A-2와 「[GitHub 워크시트 저장소 가이드](github-worksheet-repo-guide.md)」를 봅니다.
