# 대상 객체 카드 작성 가이드

교재: 2.5절 대상 객체 카드: 대상 객체·속성·관계를 한 장에 · 쓰는 곳: 문서 템플릿 `worksheet.md`의 「서비스가 다루는 대상 객체·속성·관계를 정리한 대상 객체 카드」

## 이 가이드에서 볼 것

대상 객체 카드는 이벤트 보드의 대상 객체 레인을 표 한 장으로 옮기는 작업입니다. 이 가이드는 `worksheet.md`의 표에 행을 늘리고 칸을 채우는 요령, 개념 ERD를 사진이나 글자 그림으로 넣는 방법을 다룹니다. 칸마다 무엇을 쓰는지는 교재 2.5의 [실습 안내] 표와 박준혁 예제 표를 봅니다.

## 템플릿에서 쓰는 곳

`worksheet.md`를 열고 연필 아이콘을 눌러 편집합니다(부록 A-2). 「서비스가 다루는 대상 객체·속성·관계를 정리한 대상 객체 카드」 제목 아래 표를 찾습니다.

**행 늘리기.** 대상 객체 하나가 표의 한 줄입니다. 템플릿에는 빈 줄이 여섯 개 있고, 대상 객체가 더 많으면 빈 줄 한 줄을 통째로 복사해 바로 아래에 붙입니다. 맨 위 제목 줄과 `|---|` 줄은 건드리지 않습니다. 다 쓴 뒤 남은 빈 줄은 지웁니다.

**칸 안에 쓰는 요령.**

- 칸 안에서는 줄을 바꾸지 않고, `|` 기호를 쓰지 않습니다. 둘 다 표를 깨뜨립니다.
- 핵심 속성 칸은 필수와 선택을 ` / `로 나누고, 한쪽에 여러 항목이 있으면 ` · `로 나눕니다. 예) `필수: 날짜 · 제목 / 선택: 메모`
- 관계는 양쪽 대상 객체 이름과 숫자를 함께 씁니다. 예) `대상 객체A 1:N 대상 객체B`. 상대 대상 객체의 행에도 같은 관계를 거꾸로 적습니다.
- 저장 전에 편집 화면 위쪽의 미리 보기(Preview) 탭에서 표가 제대로 보이는지 확인하고, "Commit changes"로 저장합니다.

**개념 ERD 넣기.** 표 아래 "개념 ERD" 줄 밑에 두 가지 방법 중 하나로 넣습니다.

1. **손그림 사진.** 종이에 그려 사진을 찍고, 내 워크시트 저장소에 Add file → Upload files로 올립니다. 파일 이름은 영문 소문자로, 띄어쓰기 없이 짓습니다(예: `erd.jpg`). 그다음 "손그림이라면 …" 안내 문장 아래에 새 줄을 만들고 `![개념 ERD](erd.jpg)`처럼 내 파일 이름으로 적습니다. 괄호 안 파일 이름이 올린 파일 이름과 글자 하나까지(확장자 `.jpg`·`.png`까지) 같아야 사진이 보입니다. 사진을 쓰면 아래의 빈 글자 그림 상자는 지워도 됩니다.
2. **글자 그림.** 템플릿에 이미 있는 ```` ```text ```` 로 시작해 ```` ``` ```` 로 끝나는 빈 상자 안, 두 줄 사이에 그립니다. 이 상자 안에서는 글자 폭이 일정해 상자와 선을 글자로 그려도 모양이 유지되고, `|` 기호도 써도 됩니다. 상자에는 대상 객체 이름만, 선 끝에는 1·N·M만 적습니다. 시작 줄과 끝 줄의 백틱 세 개는 지우지 않습니다.

## 자주 하는 실수와 고친 예

- **화면 이름을 대상 객체로 적었다** (택배 앱 예: "배송 조회 화면") → 그 화면이 보여 주는 "것"을 적습니다: "배송". 여러 개 쌓이고 따로 찾는지 다시 묻습니다.
- **계산되는 값을 속성으로 넣었다** (도서관 앱 예: 대출 기록에 "연체 일수") → 반납 예정일과 반납일로 계산되므로 뺍니다. 입력하는 칸만 남깁니다.
- **값을 대상 객체로 올렸다** (도서관 앱 예: 장르 "소설"을 따로 한 줄) → 장르는 내용 자체가 의미인 값이므로 "책" 행의 속성 칸으로 보내고, 엔티티·값 메모에 "장르는 값"이라고 적습니다.
- **관계를 한쪽에만 적었다** (도서관 앱 예: 회원 행에는 "회원 1:N 대출 기록", 대출 기록 행의 관계 칸은 비어 있음) → 상대 행에도 "대출 기록 N:1 회원"처럼 거꾸로 적습니다.
- **관계선을 화면 이동으로 그렸다** ("목록 → 상세") → ERD의 선은 데이터가 이어져 있다는 뜻입니다. 화면 이동은 Part 3의 화면 흐름 순서표에 씁니다.

## 완료 기준 체크리스트 확인 방법

표 아래 체크리스트의 `- [ ]`를 `- [x]`로 바꾸면 완료 표시가 됩니다.

- [ ] **이벤트 보드 대상 객체 레인의 카드를 빠짐없이 옮겼다 (표의 한 행으로, 또는 다른 행의 속성 칸으로)** → Figma의 대상 객체 레인 카드를 하나씩 짚습니다. 카드마다 표에 행이 있거나, 속성으로 보냈다면 어느 대상 객체의 핵심 속성 칸에 들어갔는지 찾을 수 있어야 합니다.
- [ ] **대상 객체마다 핵심 속성을 3~6개 적었다 (계산되는 값은 뺐다)** → 행마다 필수와 선택을 합친 항목 수를 셉니다. 항목마다 "직접 입력하는 값인가, 다른 칸으로 계산되는 값인가"를 물어 계산되는 값은 지웁니다. 일곱 개 이상이면 화면에서 꼭 쓰는 것만 남깁니다.
- [ ] **관계에 1:1 / 1:N / N:M을 표시했다** → 관계 칸마다 숫자 표시가 있는지, 상대 행과 서로 맞는지(한쪽이 1:N이면 다른 쪽은 N:1) 봅니다.
- [ ] **엔티티와 값을 구분했다** → 엔티티·값 메모 칸이 빈 행이 없는지 봅니다. 번호로 추적되는 대상 객체인지, 속성 중 값이 무엇인지 적혀 있어야 합니다.
- [ ] **개념 ERD를 그렸다** → 미리 보기에서 사진이 보이거나 글자 그림이 깨지지 않는지 확인합니다. 표의 대상 객체가 모두 상자로 있는지도 셉니다.

- 다 쓴 표는 교재 2.5 [실습 안내]의 점검 지시문으로 Claude에게 지적을 받습니다(부록 A-1). 지적이 많으면 "가장 먼저 고칠 것 세 가지만 골라 줘"라고 되묻습니다.
- 사진 올리기와 저장이 막히면 부록 A-2를 봅니다.
