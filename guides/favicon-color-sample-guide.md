# 파비콘·컬러 샘플 가이드

교재: 4.5절 리소스 마무리: 파비콘·컬러 샘플·흑백 점검 · 지시문: 지시문 킷의 「컬러 샘플·파비콘·흑백 보기 리소스 추출 지시문」 · 만드는 파일: `brand-resources.html`(새 파일), `prototype-improved.html`(흑백 보기 버튼 추가), `favicon.svg` · 쓰는 곳: 워크시트 문서 「테마별로 만든 첫 프로토타입과 버전 기록」의 개선 프로토타입 행 "다음에 할 일"

## 이 가이드에서 볼 것

- 지시 한 번으로 리소스 페이지와 흑백 보기 버튼을 받고, 그다음 **고르기 두 번**(기본 색 하나, 파비콘 하나)과 **고치기**(흑백에서 걸린 곳)를 합니다.
- 기본 색은 명암 대비를 숫자로 확인하고, 파비콘은 16px 크기에서 알아보이는지로 고릅니다.
- 흑백에서 걸린 곳은 색을 바꾸지 않고 라벨·기호·무늬를 더해 고칩니다.

왜 이 일을 하는지와 흑백 점검의 세 가지 확인 기준은 교재 4.5절에 있습니다. Code 탭 기본 조작은 「[Claude Code 프로토타이핑 따라 하기](claude-code-prototyping-guide.md)」와 부록 A-5를 봅니다.

## 시작 전에

- [ ] 4.4절의 개선 프로토타입 `prototype-improved.html`이 작업 폴더에 있다.
- [ ] 지시문 맨 앞에 복사본 한 줄을 더했다: "작업 전에 prototype-improved.html 을 prototype-improved-before-resources.html 로 복사해 둬."
- [ ] 컬러 샘플에 넣을 파일 목록에서 이름에 `-before-`가 들어간 복사본을 **모두** 뺐다. 교재 예시는 `-before-states`만 적었지만 Day 4에 만든 복사본(`-before-skill` 등)도 같습니다.
- [ ] 파비콘 후보 세 가지를 정했다. 교재 예시를 그대로 써도 되고, 내 서비스의 핵심 대상 객체를 닮은 단순한 모양으로 바꿔도 됩니다.

## 1단계 · 지시 보내고 결과 확인하기

**이렇게 나오면 정상**
- `brand-resources.html`이 새로 생기고, 열면 컬러 샘플(파일마다 한 줄, 견본 칸 옆에 `#`으로 시작하는 색 값)과 파비콘 후보 3개 × 16·32·64px이 보입니다.
- `prototype-improved.html`에 "흑백으로 보기" 버튼이 생겼고, 누르면 화면 전체가 회색, 한 번 더 누르면 원래 색입니다. 다른 영역은 복사본과 같습니다.
- 대화 끝에 "색으로만 구분되는 곳" 목록이 있습니다.

> [캡처 예정] 공통: brand-resources.html 의 파일별 컬러 샘플 줄과 파비콘 후보 세 크기가 보이는 화면
> [캡처 예정] 공통: 흑백으로 보기를 켠 개선 프로토타입 화면 (가상 프로필)

**다르게 나오면 이렇게 다시 지시합니다**
- 색 값이 안 보인다 → "견본 칸마다 색 값(#으로 시작하는 6자리)을 글자로 함께 적어 줘."
- 어느 줄이 어느 파일인지 모르겠다 → "줄 맨 앞에 파일 이름을 적고, 배경·글자·강조·선 순서로 칸을 맞춰 줘."
- 복사본 파일이 섞였다 → "이름에 -before- 가 들어간 파일은 컬러 샘플에서 빼 줘."
- 버튼 말고 다른 곳도 바뀌었다 → "흑백 보기 버튼 말고 바뀐 곳은 prototype-improved-before-resources.html 과 같게 되돌려 줘."
- 걸린 곳 목록이 없다 → "흑백 보기에서 색으로만 구분되는 곳을 영역 이름과 함께 목록으로 알려 줘. 아직 고치지 마."

## 2단계 · `brand-resources.html` 읽고 기본 색 고르기

1. 한 줄이 파일 하나입니다. 같은 역할의 칸(예: 강조)을 위아래로 훑어 파일마다 어떻게 다른지 봅니다.
2. 개선 프로토타입 줄에 강조색이 여러 개라면 통합하면서 섞인 것입니다. 4.6절에서 하나로 맞추므로 지금은 그중 하나를 고르는 것으로 충분합니다.
3. 후보를 두세 개로 줄인 뒤 숫자로 확인합니다: "brand-resources.html 의 강조색 후보 {색 값들}을 흰 바탕 위 글자색으로 쓸 때의 명암 대비 값을 표로 계산해 줘. 파일은 고치지 마." 본문 글자 기준 **4.5:1 이상**이면 글자색으로도 쓸 수 있습니다.
4. 흑백 보기를 켠 상태에서 그 색의 버튼이 묻히지 않는지도 봅니다.
5. 고른 값을 `#`까지 6자리 그대로 복사해 둡니다.

## 3단계 · 파비콘 고르고 `favicon.svg`로 저장하기

1. 브라우저 확대 비율을 100%로 두고 16px 칸을 봅니다. 화면에서 한 걸음 물러나서도 무엇인지 알아보이면 통과입니다.
2. 흑백 보기에서도 모양이 살아 있는지 봅니다.
3. 고른 후보를 저장하게 합니다: "{고른 후보}를 favicon.svg 로 작업 폴더 맨 위에 저장해 줘. 바깥 주소나 글꼴 파일을 불러오지 않게 하고, 글자가 들어 있으면 글자를 도형으로 바꿔 줘." 글자를 그대로 두면 컴퓨터마다 다른 글꼴로 보일 수 있습니다.
4. 실제 탭에서 확인합니다: "brand-resources.html 의 탭 아이콘을 favicon.svg 로 연결해 줘." 브라우저 탭 맨 앞에 아이콘이 보이면 정상입니다. 이 파일은 4.7절에서 배포 폴더에 함께 들어갑니다.

> [캡처 예정] 공통: 브라우저 탭에 favicon.svg 가 보이는 화면

## 4단계 · 흑백에서 걸린 곳 고치기

1. 흑백 보기를 켜고 교재 4.5절의 세 가지 확인 기준으로 화면을 직접 훑습니다. Claude Code의 목록에 없는 곳도 내가 찾으면 목록에 더합니다.
2. 한 번에 한 곳씩 고치게 합니다: "흑백 보기에서 걸린 곳 중 {번호}번을 고쳐 줘. 색은 바꾸지 말고 {글자 라벨 / 기호 / 빗금·점선 무늬}를 더해 줘. 다른 영역은 고치지 말고, 끝나면 바뀐 줄 범위를 알려 줘."
3. 고칠 때마다 흑백 보기를 다시 켜서 확인합니다. 연한 글자가 묻히는 곳은 글자색을 진하게 바꿔 명암 차이를 키웁니다.
4. 버튼이 아니라 컴퓨터 화면 전체를 회색조로 보고 싶다면 Mac은 시스템 설정 → 손쉬운 사용 → 디스플레이 → 색상 필터, Windows는 설정 → 접근성 → 색 필터에서 회색조를 켭니다. 확인이 끝나면 꼭 끕니다.

> [캡처 예정] 공통: 흑백 보기에서 라벨·무늬를 더하기 전과 뒤를 나란히 놓은 화면 (가상 프로필)

## 5단계 · 버전 기록에 적기

개선 프로토타입 행 "다음에 할 일"에 이렇게 적습니다: `기본 색 {색 값} · 파비콘 {고른 후보} (favicon.svg) → 4.6 테마 일체감 통합에 사용`. 흑백 보기에서 고친 곳은 같은 행 "바뀐 점·관찰 메모"에 한 줄로 더합니다.

## 자주 하는 실수와 고친 예

- **상태를 색 점으로만 나눴다** (배달앱 예: "조리 중 · 배달 중 · 완료"를 노랑·파랑·초록 점으로만) → 흑백에서 모두 같은 회색이 됩니다. 점 옆에 글자 라벨을 붙이고, 완료에는 ✓를 더합니다.
- **색만 더 진하게 바꿨다** (도서관 앱 예: 연체 도서의 빨간 글자를 더 진한 빨강으로) → 흑백에서는 여전히 구분되지 않습니다. "연체 3일" 라벨과 굵은 테두리를 더합니다.
- **파비콘에 다 넣었다** (택배 앱 예: 상자·트럭·글자를 한 아이콘에) → 16px에서 뭉개집니다. 상자 하나만 남깁니다.
- **복사본까지 컬러 샘플에 넣었다** → 이미 버린 색이 후보로 섞입니다. `-before-` 파일은 뺍니다.

## 막혔을 때

- **흑백 보기가 일부 영역에만 적용된다.** "흑백 보기가 {영역 이름}에는 적용되지 않아. 페이지 전체가 회색조로 바뀌게 고쳐 줘. 모양은 바꾸지 마."
- **흑백을 끄면 원래 색으로 돌아오지 않는다.** "흑백으로 보기 버튼을 한 번 더 누르면 처음 색으로 정확히 돌아오게 고쳐 줘."
- **파비콘이 16px에서 깨진다.** "{후보} 파비콘을 16px용으로 다시 그려 줘. 선을 두껍게, 세부는 줄여 줘."
- **색 값이 실제 화면과 다른 것 같다.** "{파일}에서 강조색 {색 값}이 쓰인 줄 번호를 보여 줘. 고치지 마."라고 물어 직접 확인합니다.
- **명암 대비를 넘는 후보가 없다.** "{후보 색}과 같은 계열에서 흰 바탕 명암 대비 4.5:1 이상인 색 3개를 brand-resources.html 에 한 줄로 더해 줘."
- **파일이 망가졌다.** "prototype-improved-before-resources.html 의 내용으로 prototype-improved.html 을 되돌려 줘. 복사본은 그대로 둬." 그다음 1단계부터 다시 합니다.
- **사용 한도에 걸렸다.** 사전 안내의 조건에 맞는 다른 회사의 AI 코딩 도구로 같은 작업 폴더를 열고 이어 합니다. 지시문은 그대로, `@` 표기만 그 도구 방식으로 바꿉니다.
