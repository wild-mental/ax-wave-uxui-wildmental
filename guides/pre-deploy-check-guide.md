# 배포 전 점검과 정적 배포 가이드

교재: 4.7절 정적 배포: 공개하기 전에 지우기 · 쓰는 곳: 워크시트 문서의 「공개 전 개인정보·품질을 확인한 배포 전 점검표와 배포 링크」 · 작업 폴더의 `deploy/`

## 이 가이드에서 볼 것

점검은 **지시 → 결과 → 확인 → 수정** 순서로 나눠 합니다. Claude Code가 찾은 목록을 그대로 믿지 않고, 여러분이 브라우저와 페이지 소스로 한 번 더 확인하는 것이 핵심입니다. 왜 점검하는지와 점검표 작성 예는 교재 4.7절(정하은 프로필로 실습한 예)을 봅니다. 이 가이드는 `deploy` 폴더가 준비될 때까지를 다루고, 올리는 클릭은 「[GitHub Pages 정적 배포 가이드](github-pages-deploy-guide.md)」로 넘깁니다.

지시문은 둘 중 하나를 씁니다.

- 교재 4.7절 [실습 안내]의 지시문: 한 번에 보내고, 확인한 뒤 "고쳐"로 진행합니다.
- 지시문 킷의 「배포 전 개인정보 점검·정적 배포 준비 지시문」: [점검] · [수정] · [배포 준비] 세 번으로 나눠 보냅니다. 아래 단계는 이 순서를 따릅니다.

교재 지시문의 `f-athlete`는 정하은 예의 데이터셋 폴더입니다. 여러분이 고른 프로필의 폴더 이름(`m-general`, `f-general`, `m-athlete`, `f-athlete` 중 하나)으로 바꿔 보냅니다.

## 0. 시작 전: 복사본 만들기

`prototype-final.html`을 고치기 전에 복사본을 만들어 둡니다. Claude Code에 "prototype-final.html 을 고치지 말고 같은 폴더에 prototype-final-before-deploy.html 로 복사해 줘"라고 보내거나, Finder에서 `Cmd+D`(Windows 파일 탐색기에서 `Ctrl+C` → `Ctrl+V`)로 복제한 뒤, 생긴 사본의 이름을 `prototype-final-before-deploy.html`로 고칩니다. 수정이 잘못되면 이 파일로 돌아갑니다. 복사본은 작업 폴더 맨 위에 두고 `deploy`에는 넣지 않습니다.

## 1. 지시: 점검만 하기

Claude Code에서 작업 폴더를 연 상태로 [점검] 지시를 보냅니다.

이렇게 나오면 정상:

- 항목마다 **파일 이름 · 위치 · 찾은 내용 · 종류**를 알 수 있는 목록이나 표가 나옵니다.
- 신체 수치 항목에는 data 폴더의 값과 **같음 / 다름**이 함께 표시됩니다.
- 파일을 고치겠다는 허락 요청이 뜨지 않습니다.

> [캡처 예정] 공통: [점검] 지시에 대한 결과 표(가상 프로필 데이터 화면)

결과가 다를 때 다시 보내는 문장:

- 위치가 없다 → "찾은 항목마다 파일 이름과 화면 위치(또는 줄 번호)를 붙여 표로 다시 보여 줘."
- 수치 대조가 빠졌다 → "화면에 나오는 숫자마다 data 폴더의 어느 파일, 어느 날짜 값과 같은지 칸을 하나 더해 보여 줘. 다른 값은 따로 표시해 줘."
- 허락 요청이 떴다 → **거절**하고 "아직 고치지 마. 점검 목록만 보여 줘."

## 2. 확인: 목록을 직접 대조하기

목록에 없다고 안심하지 않습니다. 브라우저로 `prototype-final.html`을 열고 아래를 직접 봅니다.

| 점검 항목 | 직접 확인하는 방법 |
|---|---|
| 실제 이름·이메일 | 페이지에서 `Cmd+F`(Windows `Ctrl+F`)로 내 이름, 내 아이디, `@`를 찾아봅니다 |
| 실제 신체 수치 | 화면의 숫자를 data 폴더 CSV의 같은 날짜 값과 몇 개 골라 맞춰 봅니다 |
| HTML 주석·숨긴 요소 | 페이지 소스 보기(아래 표)에서 `<!--`, `hidden`, `display: none`을 찾아봅니다 |
| 바깥 링크 | 페이지 소스에서 `http`를 찾아 Figma · 워크시트 저장소 · 문서 주소가 있는지 봅니다 |

| 페이지 소스 보기 | Mac | Windows |
|---|---|---|
| Chrome · Edge | `Cmd+Option+U` | `Ctrl+U` |
| Safari | **Safari → 설정 → 고급 → 웹 개발자를 위한 기능 보기**를 켠 뒤 `Cmd+Option+U` | (해당 없음) |

> [캡처 예정] Mac · Windows: 페이지 소스 보기에서 `<!--`를 찾은 화면

숨긴 요소 중 모달, 흑백 보기, 탭 내용처럼 **화면 기능으로 숨긴 것**은 정상입니다. 안에 메모나 실제 값이 들어 있는 것만 조치합니다.

## 3. 수정: 고를 항목만 "고쳐"

1. 목록에서 지우거나 바꿀 항목 번호를 고릅니다.
2. [수정] 지시의 `{항목 번호}` 자리에 번호를 넣어 보냅니다(교재 지시문을 썼다면 "1, 3, 4번 고쳐"처럼 보냅니다).
3. 허락 요청에서 바뀌는 줄을 읽고, 고른 항목만 바뀌는지 보고 승인합니다.

이렇게 나오면 정상: 고른 항목만 바뀌고, 페이지 맨 아래에 "모든 이름과 수치는 가상 프로필 데이터입니다"가 보입니다. 브라우저에서 새로 고쳐 2번의 확인을 한 번 더 합니다.

> [캡처 예정] 공통: 수정 뒤 페이지 맨 아래의 가상 데이터 안내 문구

결과가 다를 때: "방금 바꾼 것 중 {항목}은 내가 고르지 않았어. 그 부분만 되돌려 줘." 여러 곳이 망가졌다면 0번의 복사본으로 돌아갑니다.

## 4. 배포 준비: `deploy` 폴더 만들기

[배포 준비] 지시를 보냅니다.

이렇게 나오면 정상:

- `deploy` 폴더 안에 `index.html`, `favicon.svg` **두 파일만** 있습니다(Finder · 파일 탐색기에서 직접 열어 봅니다).
- 브라우저로 `deploy/index.html`을 열면 모든 화면이 나오고, 탭에 파비콘이 보입니다.

> [캡처 예정] Mac · Windows: `deploy` 폴더 안에 두 파일만 있는 창

결과가 다를 때 다시 보내는 문장:

- 다른 파일도 들어갔다 → "deploy 폴더에는 index.html 과 favicon.svg 만 남기고 나머지는 지워 줘. 작업 폴더의 원본은 건드리지 마."
- 파비콘이 안 보인다 → "deploy/index.html 이 같은 폴더의 favicon.svg 를 파비콘으로 쓰는지 확인하고, 아니면 고쳐 줘."
- 화면이 깨진다 → "deploy/index.html 이 deploy 폴더 밖의 파일을 불러오는 곳이 있는지 찾아서 목록으로 보여 줘."

## 5. 점검표 채우기

워크시트 저장소의 `worksheet.md`에서 배포 전 점검표의 위 여섯 행을 채웁니다. 결과 칸은 "정상", "발견 1건", "추가"처럼 짧게 쓰고, 찾는 방법 칸에는 실제로 한 방법을 씁니다. 채우는 예는 교재 4.7절의 표를 봅니다. "배포 후 재확인" 행은 6번에서 채웁니다.

자주 하는 실수와 고친 예 (도서관 앱 예):

- 결과 칸에 "없음"만 적었다 → "정상 (소스 보기에서 `<!--` 검색, 0건)"처럼 확인한 방법을 남깁니다.
- 조치 칸에 "수정함"만 적었다 → "사서 실명을 '담당 사서'로 교체"처럼 무엇을 어떻게 바꿨는지 씁니다.
- Claude Code 목록만 옮겨 적었다 → 2번의 직접 확인을 하고 나서 적습니다.

## 6. 올리기와 배포 후 재확인

1. 「[GitHub Pages 정적 배포 가이드](github-pages-deploy-guide.md)」를 따라 `deploy` 안의 두 파일을 배포 전용 공개 저장소에 올립니다.
2. 공개 주소를 시크릿 창과 휴대폰으로 엽니다. 2번의 확인 중 이름 찾기와 소스 보기를 **실제 주소에서 한 번 더** 합니다.
3. "배포 후 재확인" 행의 결과 칸에 주소를 적고, 버전 기록 아래 "배포 링크"에도 적습니다.

> [캡처 예정] 공통: 시크릿 창에서 연 공개 주소와 파비콘

## 막혔을 때

- **Claude Code가 점검 단계에서 파일을 고쳤다** → 0번의 복사본에서 `prototype-final.html`을 되살리고, "점검만 해 줘. 고치지 마."를 첫 줄에 두어 다시 보냅니다.
- **목록이 너무 길다** → "개인정보 후보만 남기고, 가상 프로필 데이터와 같은 값은 빼고 다시 보여 줘."
- **어떤 수치가 가상 값인지 모르겠다** → 화면의 날짜를 보고 내 프로필 CSV를 표 계산 프로그램으로 열어 같은 날짜 줄을 찾습니다. 맞는 값이 없으면 가상 값이 아닙니다.
- **실수로 실제 값을 이미 올렸다** → 그 저장소를 지우고 새로 만듭니다. 「GitHub Pages 정적 배포 가이드」의 「잘못 올렸을 때」를 봅니다.
- **`deploy` 폴더에서 `index.html`이 `index`로만 보인다** → 확장자가 숨겨져 있습니다. 「Claude Code 데스크톱 앱 설치 (Mac판 · Windows판)」의 확장자 보이게 하기를 따릅니다.
- **수정 뒤 화면 일부가 사라졌다** → "방금 수정 전과 후에서 바뀐 부분을 목록으로 보여 줘."라고 물어 원인을 찾고, 고치기 어려우면 복사본으로 돌아가 3번부터 다시 합니다.
- Claude Code 조작은 부록 A-5, 워크시트 저장소는 부록 A-2와 「GitHub 워크시트 저장소 가이드」를 봅니다.
