# 짝 사용성 테스트 진행 가이드

교재: 4.4절 사용성 점검: 과업으로 시험하고 고치기 · 쓰는 곳: 워크시트 문서 `worksheet.md`의 「사용자 과업으로 시험한 사용성 테스트 기록표」

## 이 가이드에서 볼 것

짝과 서로의 프로토타입을 시험하는 한 시간을 진행하는 순서, 두 역할이 말할 문장, 관찰을 적는 법, 우선순위를 정하는 법을 다룹니다. 과업 시나리오의 세 조건, 휴리스틱 7가지의 확인 질문, 기록표 칸 설명은 교재 4.4절을 봅니다. 역할 이름은 교재와 같습니다. 내 프로토타입을 시험할 때 나는 **테스트하는 나**, 짝은 **써 보는 짝**입니다.

## 진행 순서와 시간

전체 순서와 시간은 교재 4.4절 [실습 안내]의 "진행 순서(60분)"를 따릅니다. 아래는 단계마다 두 사람이 할 일입니다.

| 단계 | 테스트하는 나 | 써 보는 짝 |
|---|---|---|
| 시나리오 쓰기 | 과업 4개를 기록표 과업 칸에 씁니다. 그중 하나는 찾기 과업으로 하고 "찾기"를 붙입니다. 시험할 파일(`prototype-merged.html`)을 브라우저로 열어 첫 화면에 둡니다 | 내 시나리오를 씁니다 |
| 내 프로토타입 시험 | 프로필 카드를 1분 보여 주고, 과업을 하나씩 읽어 줍니다. 초시계를 재고, 본 것을 적습니다 | 프로필 속 사람이 되어 화면을 누르며 생각을 소리 내어 말합니다 |
| 역할 바꾸기 | 짝의 화면을 써 보는 짝이 됩니다 | 테스트하는 나가 됩니다 |
| 휴리스틱 평가 | 혼자 내 화면을 7가지 원칙으로 봅니다. "아니오"가 나온 원칙만 기록표에 더합니다 | 혼자 같은 일을 합니다 |
| 우선순위 | 막힘·헤맴·거슬림을 붙이고 고칠 이슈를 최대 3개 고릅니다 | 같은 일을 합니다 |

**한 판(15분) 나누기.** 프로필 카드 1분 → 시작하는 말 1분 → 과업마다 최대 3분 → 끝맺는 질문 1~2분입니다. 과업 4개가 모두 3분씩 걸리면 시간이 모자라므로, 찾기 과업과 가장 중요한 과업을 먼저 시험합니다.

**시작 전에 화면 정리.** 노트북에서 Claude Code 창, 워크시트, 다른 탭을 닫거나 내리고 프로토타입 탭 하나만 남깁니다. 과업이 끝날 때마다 새로 고침해서 첫 화면으로 돌아간 뒤 다음 과업을 읽습니다.

## 과업 시나리오 쓰기: 실수와 고친 예

| 실수 | 고친 예 (관통 예제 밖) |
|---|---|
| 메뉴 이름이 들어 있다: "'빌린 책' 메뉴에서 반납일을 확인하세요" | "다음 주에 여행을 갑니다. 그 전에 책을 돌려줘야 하는지 확인해 보세요" |
| 끝이 없다: "배달앱을 자유롭게 둘러보세요" | "어제 시킨 떡볶이를 똑같이 다시 주문하려고 합니다. 결제 직전 화면까지 가 보세요" |
| 조작 순서를 알려 준다: "검색창에 '세탁'을 입력하세요" | "내일 아침까지 맡긴 셔츠를 받을 수 있는지 알아보세요" |
| 정답이 둘 이상이다: "가까운 지점을 찾으세요" | "지금 있는 곳에서 걸어서 갈 수 있는 지점의 문 닫는 시간을 찾아보세요" |

시나리오를 다 쓰면 과업마다 "어느 화면, 어떤 글자가 보이면 성공"인지 한 줄로 따로 적어 둡니다. 짝에게는 보여 주지 않습니다.

## 테스트하는 나의 대본

- **시작:** "오늘은 화면을 시험하는 거지 당신을 시험하는 게 아니에요. 막히면 제 화면이 잘못 만들어진 거예요. 누르면서 생각나는 것을 그대로 소리 내어 말해 주세요. 저는 도와드리지 않고 지켜보기만 할게요."
- **과업 읽기:** 과업 문장을 그대로 두 번 읽고 종이나 화면에 띄워 둡니다. 읽은 뒤 초시계를 누릅니다.
- **조용해졌을 때:** "지금 무엇을 찾고 계세요?" / "지금 무슨 생각을 하세요?"
- **짝이 물을 때:** "혼자 하신다면 어떻게 하실 것 같아요?" / "끝까지 해 보시고 나중에 말씀드릴게요."
- **3분이 지났을 때:** "좋아요, 여기까지 하고 다음으로 가겠습니다." 화면을 첫 화면으로 돌립니다.
- **끝맺는 질문:** "가장 헷갈렸던 곳은 어디였어요?" / "이 화면에서 처음 보는 말이 있었나요?" 그리고 "고맙습니다. 막힌 곳은 제가 고칠 부분이에요."

**하지 않는 말.** "그 위에 있어요", "거의 다 왔어요", "아, 그건 버튼이에요", "이건 원래 ~하는 거예요". 이끄는 말 한마디로 그 과업은 실패가 됩니다(교재 4.4절의 성공 여부 칸). 고개 끄덕임, 화면 가리키기, 한숨도 이끄는 말입니다.

## 써 보는 짝의 대본

- 화면을 볼 때: "지금 ~를 찾고 있어요." / "이 이름을 보니 ~가 나올 것 같아요."
- 누르기 전에: "~라고 쓰여 있어서 이걸 눌러 볼게요."
- 헷갈릴 때: "여기서 어디로 가야 할지 모르겠어요." / "~와 ~가 같은 건가요?"
- 끝났다고 생각할 때: "찾은 것 같아요. 여기 ~라고 나와요."

**하지 않는 것.** 디자인을 평가하거나("색이 예뻐요") 고칠 방법을 말하지 않습니다. 프로필 속 사람이 실제로 할 행동만 합니다. 잘 안 풀려도 일부러 맞히려고 애쓰지 말고, 막히면 막혔다고 말하면 됩니다.

## 관찰을 적는 법

과업 중에는 기록표에 바로 쓰지 말고 메모에 **"시간 · 행동 · 혼잣말"** 순서로 짧게 적습니다. 끝난 뒤 기록표의 막힌 곳 칸으로 옮깁니다.

| 해석으로 적은 것 | 본 그대로 적은 것 |
|---|---|
| 메뉴를 헷갈려함 | 0:20 "내 정보"를 먼저 엶 → 0:45 뒤로 가기 → 1:10 "빌린 책" 엶 |
| 버튼을 못 찾음 | 결제 화면에서 스크롤을 두 번 오르내림. "다시 주문은 어디 있지?" |
| 금방 함 | 0:35 성공. 처음 누른 곳이 정답 |

## 휴리스틱 평가 순서

혼자 하는 10분 동안 원칙 하나를 화면 전체에 비춰 보고 다음 원칙으로 넘어갑니다. 확인 질문은 교재 4.4절 표를 봅니다. 아래 "먼저 볼 곳"은 그 원칙의 문제가 자주 숨는 곳입니다.

- [ ] 지금 무슨 일이 일어나는지 보여 준다 — 저장 버튼을 누른 직후 화면
- [ ] 사용자의 말을 쓴다 — 메뉴·카드 제목을 용어 대조표와 나란히 놓고
- [ ] 언제든 되돌리고 빠져나갈 수 있다 — 입력 창, 팝업, 삭제 버튼
- [ ] 같은 것은 같게 보인다 — 화면 두 개를 나란히 놓고 같은 역할의 버튼
- [ ] 실수하기 전에 막고, 빈틈을 안내한다 — 빈 상태·오류·이상치 화면의 문구
- [ ] 외우게 하지 말고 보고 고르게 한다 — 목표 수치나 지난 기록이 필요한 입력 화면
- [ ] AI 판단의 근거와 한계가 보인다 — AI가 판단·권유를 보여 주는 카드

## 우선순위 정하기

순서 규칙(막힘 → 헤맴 → 거슬림, 같은 순위면 찾기 과업 먼저)은 교재 4.4절을 따릅니다. 헷갈릴 때는 이렇게 가립니다.

- 성공했어도 처음 누른 곳이 틀렸거나 눈에 띄게 오래 걸렸으면(예: 1분 넘게) 헤맴입니다.
- "부분 성공"은 끝까지 가지 못한 부분이 과업의 목적이면 막힘, 곁가지면 헤맴입니다.
- 원칙 점검 행은 그 원칙 때문에 과업이 막혔으면 막힘, 아니면 헤맴이나 거슬림입니다.
- 같은 화면에서 나온 이슈 둘은 하나로 묶어도 됩니다.

## 기록표 예 (관통 예제 밖)

도서관 앱을 시험한 예입니다.

| 과업 | 성공 여부 | 걸린 시간 | 막힌 곳 | 고칠 점 |
|---|---|---|---|---|
| 과업 2 찾기: "다음 주에 여행을 갑니다. 그 전에 책을 돌려줘야 하는지 확인해 보세요." | 성공 | 1분 50초 | "내 정보"부터 열고 40초 뒤 뒤로 가기. 첫 화면의 "내 서재" 카드를 두 번 지나침. "반납일은 어디 있지?" | "내 서재"를 "빌린 책 · 반납일"로, 용어 대조표도 고침 |
| 과업 3: "읽던 책을 일주일 더 빌리려고 합니다. 연장해 보세요." | 실패 | 3분(중단) | 책 상세 화면 맨 아래 "기간 연장" 글자 링크를 지나침. "연장 버튼이 없네" | 상세 화면 맨 위에 "일주일 더 빌리기" 버튼 |
| 원칙 점검: 지금 무슨 일이 일어나는지 보여 준다 | 아니오 | — | 예약 버튼을 눌러도 화면이 바뀌지 않음 | 누른 뒤 "예약했습니다 · 순서 3번째" 안내 |

우선순위: 과업 3(막힘) → 과업 2(헤맴, 찾기 과업) → 지금 무슨 일이 일어나는지 보여 준다 원칙(헤맴).

고를 이슈가 정해지면 기록표를 「사용성 테스트 결과 반영 개선 지시문」(교재 4.4절, 자료실 지시문 킷)에 붙여 넣어 개선 프로토타입을 만듭니다. 이름을 바꿨다면 용어 대조표도 함께 고칩니다.

## 막혔을 때

- **짝이 과업을 너무 빨리 끝내 관찰할 것이 없을 때:** 실패가 아니라 좋은 결과입니다. "0:30 성공, 첫 시도 정답"이라고 적고, 남는 시간에 찾기 과업을 하나 더 시험합니다.
- **짝이 과업 문장을 이해하지 못할 때:** 문장을 그대로 한 번 더 읽어 줍니다. 그래도 모르면 그 과업은 시나리오 문제이니 표시해 두고 다음 과업으로 갑니다. 다른 말로 풀어 설명하지 않습니다.
- **프로토타입이 열리지 않거나 버튼이 동작하지 않을 때:** 그 과업은 건너뛰고 "동작 안 함"으로 적어 1순위 이슈로 둡니다. 파일이 안 열리면 「Claude Code 프로토타이핑 따라 하기」의 막혔을 때를 봅니다.
- **짝이 프로필 사람이 되기 어려워할 때:** 프로필 카드에서 "이 사람이 오늘 하려는 일" 한 줄만 다시 보여 줍니다.
- **짝이 없을 때(인원이 홀수일 때):** 세 사람이 돌아가며 테스트하는 나·써 보는 짝·기록하는 사람을 맡습니다. 기록하는 사람은 초시계와 메모만 맡습니다.
- 워크시트를 저장하는 법은 부록 A-2와 「GitHub 워크시트 저장소 가이드」를 봅니다.
