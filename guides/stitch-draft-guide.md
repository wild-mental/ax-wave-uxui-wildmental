# Stitch 시안 만들기 가이드

교재: 3.5절 Stitch로 테마별 시안 비교하기 · 쓰는 곳: Figma 템플릿의 「Google Stitch로 만든 테마별 화면 시안 비교표」 페이지 · 지시문: 지시문 킷의 「Stitch 테마별 시안 생성 지시문」

## 이 가이드에서 볼 것

같은 화면 설명에 DESIGN.md만 바꿔 넣어 테마별 시안을 뽑고, 비교표에 붙여 세 기준으로 적는 **실습 흐름**을 다룹니다. 로그인, 새 프로젝트, 파일 첨부, 이미지 내보내기 같은 Stitch 조작은 [「Stitch 시작 가이드」](stitch-start-guide.md)와 부록 A-4를 봅니다. 비교 기준과 칸 설명은 교재 3.5를 봅니다.

핵심 세 가지:

1. 화면 설명은 **한 번만** 쓰고, 테마마다 DESIGN.md만 바꿉니다.
2. 테마마다 데스크톱 1장 · 모바일 1장으로 시작하고, 고치기는 **한 번에 한 가지, 두세 번까지**만 합니다.
3. 목적은 비교입니다. 결론("어느 테마의 어느 부분")을 얻으면 멈춥니다.

## 전체 흐름

| 단계 | 할 일 | 끝났다는 표시 |
|---|---|---|
| 준비 | DESIGN.md 2~3개, 그릴 화면 2~3개, 화면 설명 원본 | 메모 파일 하나에 화면 설명이 모여 있음 |
| 1 | 첫 테마로 데스크톱 · 모바일 시안 | 정상 확인 다섯 가지 통과 |
| 2 | 고치기 (한 가지씩, 두세 번까지) | 고친 시안을 이미지로 내보냄 |
| 3 | 다음 테마로 같은 화면 | 테마 수 × 화면 수만큼 이미지 |
| 4 | 비교표에 붙이고 흑백으로 보기 | 세 기준 + 한 줄 결론 |

## 준비: 화면 설명 원본 만들기

1. 쇼핑 목록에서 고른 `DESIGN-<테마이름>.md` 파일 2~3개를 한 폴더에 모읍니다.
2. 화면 흐름 순서표의 화면 목록에서 그릴 화면 2~3개를 고릅니다. 고르는 기준은 교재 3.5 「어떤 화면을 그려 볼까」입니다.
3. 지시문 킷의 「Stitch 테마별 시안 생성 지시문」을 메모장(Windows)이나 텍스트 편집기(Mac)에 붙여 넣고, 화면마다 `{ }`를 채웁니다. 들어갈 내용과 화면 이름은 화면 목록, 용어 대조표, 내 프로필 데이터에서 가져옵니다. 교재 3.5의 지시문 예시가 다 채운 모습입니다.
4. `[디자인 규칙]` 줄의 파일 이름 부분만 비워 둔 채 이 메모를 저장합니다. 이것이 **화면 설명 원본**입니다. 테마를 바꿀 때는 이 원본을 복사해서 파일 이름만 바꿉니다.
5. Figma에서 내 파일의 「Google Stitch로 만든 테마별 화면 시안 비교표」 페이지를 열어 둡니다.

## 1단계 · 첫 테마로 시안 뽑기

**지시.** Stitch에서 새 프로젝트를 만들고 이름에 테마 이름을 넣습니다(예: `bright-coaching`). 화면 설명 원본의 첫 화면을 붙여 넣고, `DESIGN-<테마이름>.md`를 첨부하거나 내용을 이어 붙입니다. 첨부·붙여 넣기 조작은 「Stitch 시작 가이드」를 봅니다.

**결과.** 잠시 뒤 데스크톱 화면 시안이 나옵니다.

**확인 — 이렇게 나오면 정상입니다.**

- [ ] 화면 설명의 "들어갈 내용"이 **빠짐없이** 보인다 (교재 3.5 예시라면 네 줄이 모두)
- [ ] 주요 버튼이 설명대로 하나다
- [ ] 화면 이름·버튼 문구가 내가 적은 말 그대로다 (영어나 다른 말로 바뀌지 않았다)
- [ ] 숫자가 내가 넣은 값뿐이다 (지어낸 그래프·점수·사람 사진이 없다)
- [ ] 쓰인 색이 DESIGN.md 색 항목에 있는 색이다

> [캡처 예정] 공통: 첫 테마의 데스크톱 시안이 나온 Stitch 화면 (가상 프로필 데이터)

다섯 가지를 통과하면 같은 프로젝트에서 "같은 화면을 모바일로도 만들어 줘."라고 이어서 요청합니다. 모바일 시안에서 정보 순서가 데스크톱과 같은지 봅니다.

> [캡처 예정] 공통: 같은 프로젝트에서 이어 만든 모바일 시안 (가상 프로필 데이터)

**바로 내보내기.** 고치기 전에 지금 시안을 이미지로 먼저 내보냅니다. 고친 결과가 더 나빠지면 이 이미지가 되돌아갈 복사본입니다. 이미지 이름에 테마 이름과 화면 이름을 넣으면 비교표에 붙일 때 헷갈리지 않습니다.

## 2단계 · 고치기: 한 번에 한 가지

확인에서 걸린 것만 고칩니다. 한 문장에 **어디가 · 지금 어떻고 · 어떻게 바뀌어야 하고 · 무엇은 그대로 둘지**를 넣습니다. 결과가 다를 때 쓰는 다시 지시 문장 예입니다.

| 이렇게 나왔다 | 다시 지시하는 문장 |
|---|---|
| DESIGN.md에 없는 색이 나왔다 | 주요 버튼이 첨부한 DESIGN.md에 없는 색입니다. DESIGN.md "색" 항목의 주색으로 바꿔 주세요. 배치와 문구는 바꾸지 마세요. |
| 여러 곳에 없는 색이 섞였다 | 첨부한 DESIGN.md의 색 목록에 있는 색만 쓰도록 화면 전체의 색을 다시 맞춰 주세요. 배치와 문구는 그대로 둡니다. |
| 들어갈 내용 하나가 빠졌다 | "{빠진 내용}"이 화면에 없습니다. {어느 카드} 아래에 추가해 주세요. 다른 부분은 바꾸지 마세요. |
| 지어낸 숫자나 그래프가 있다 | 제가 적지 않은 {그래프·숫자}를 지워 주세요. 화면에는 제가 준 값만 둡니다. |
| 문구가 영어로 나왔다 | 화면의 모든 글자를 제가 적은 한국어 문구 그대로 바꿔 주세요. 배치는 바꾸지 마세요. |
| 버튼이 여러 개 같은 크기다 | "{주요 버튼 이름}"만 주요 버튼으로 크게 두고, 나머지는 글자 링크로 바꿔 주세요. |
| 모바일에서 순서가 바뀌었다 | 모바일 화면도 데스크톱과 같은 순서({첫째} → {둘째} → {셋째})로 보이게 해 주세요. |

- 고칠 것이 여러 개면 **목적에 가장 크게 어긋나는 것 하나**부터 고칩니다.
- 고친 뒤 다시 위 다섯 가지를 확인하고, 좋아졌으면 이미지로 내보냅니다.
- 세 번 고쳐도 안 고쳐지는 문제는 그대로 두고 비교표 이유 칸에 적습니다. 그것도 그 DESIGN.md의 특징입니다.

> [캡처 예정] 공통: 색 하나를 고치라고 다시 지시하기 전과 후의 시안 (가상 프로필 데이터)

## 3단계 · 다음 테마: DESIGN.md만 바꾸기

1. 테마마다 **새 프로젝트**를 만들고 테마 이름을 붙입니다. 같은 프로젝트에서 이어 요청하면 앞 테마의 디자인이 섞일 수 있습니다.
2. 화면 설명 원본을 복사해, 파일 이름 부분만 이번 테마의 `DESIGN-<테마이름>.md`로 바꿔 붙여 넣고 그 파일을 첨부합니다. **설명의 다른 글자는 한 자도 바꾸지 않습니다.** 설명을 고치면 차이가 DESIGN.md 때문인지 설명 때문인지 알 수 없습니다.
3. 1단계 확인 다섯 가지와 2단계 고치기를 똑같이 합니다. 고친 횟수도 테마끼리 비슷하게 맞춥니다.

> [캡처 예정] 공통: 같은 화면 설명으로 만든 두 테마의 데스크톱 시안을 나란히 놓은 화면

## 4단계 · 비교표에 붙이고 흑백으로 보기

1. 내보낸 이미지를 Figma 비교표 페이지의 해당 테마 줄, 시안 화면 칸에 끌어다 놓습니다. 붙이는 조작은 부록 A-3과 「Figma 템플릿 열기·복제 가이드」를 봅니다.
2. **흑백으로 보기.** 아래 둘 중 하나를 씁니다.
   - 화면 전체를 흑백으로: Mac은 시스템 설정 → 손쉬운 사용 → 디스플레이 → 색상 필터를 켜고 "회색 음영", Windows는 설정 → 접근성 → 색 필터를 켜고 "회색조". 다 보면 다시 끕니다.
   - 이미지 하나만: Figma에서 이미지를 복제(`Cmd+D` / `Ctrl+D`)한 뒤, 복제본의 오른쪽 패널 채우기(Fill)에서 이미지 설정을 열고 채도(Saturation)를 가장 낮게 내립니다. 원본 색 이미지는 그대로 둡니다.
3. 흑백에서 볼 것: 먼저 눈에 띄는 세 가지가 색이 있을 때와 같은가, 주요 버튼이 여전히 가장 먼저 보이는가, 주의·완료 같은 상태가 글자나 모양으로도 구분되는가.
4. 세 기준(과업 수행 쉬움 · 정보 위계 · 프로필 적합성)을 ○/△/×와 이유 한 줄로 적고, 테마마다 한 줄 결론을 씁니다. 확인 방법은 교재 3.5 「비교 기준 세 가지」 표의 셋째 열입니다.

> [캡처 예정] 공통: 시안 이미지와 세 기준 · 한 줄 결론을 채운 Figma 비교표 한 줄 (가상 프로필 데이터)

> [캡처 예정] Mac · Windows: 색 필터(회색 음영 · 회색조)를 켠 상태의 비교표 페이지

## 자주 하는 실수와 고친 예

- **테마마다 설명을 조금씩 고쳤다** (도서관 앱 예: 첫 테마는 "대출 연장 버튼", 둘째는 "연장하기 버튼") → 원본 설명으로 다시 뽑습니다. 이름이 다르면 비교가 되지 않습니다.
- **한 번에 세 가지를 고쳐 달라고 했다** → 어느 지시가 무엇을 바꿨는지 모르게 됩니다. 하나씩 나눠 다시 지시합니다.
- **이유 없이 기호만 적었다** ("△") → "△ 버튼이 세 개라 첫 행동을 고민함"처럼 화면에서 본 사실을 붙입니다.
- **결론이 "밝은 코칭형이 제일 예쁨"** → 어느 화면의 어느 부분을 가져갈지, 첫 프로토타입을 어느 테마로 만들지 씁니다.
- **고친 시안만 남기고 처음 시안을 잃었다** → 다음부터 고치기 전에 내보냅니다. 지금은 Stitch 프로젝트 안의 이전 화면을 찾아 내보냅니다.

## 완료 기준 체크리스트 확인 방법

- [ ] **테마 2개 이상 × 핵심 화면 2개 이상의 시안을 붙였다** → 비교표의 시안 화면 칸에서 테마 줄마다 이미지 수를 셉니다. 테마끼리 같은 화면인지도 봅니다.
- [ ] **세 기준을 모두 ○/△/×와 이유로 평가했다** → 빈칸 없이 기호가 있고, 기호마다 화면에서 본 사실 한 줄이 붙어 있는지 봅니다.
- [ ] **테마마다 한 줄 결론을 적었다** → 결론에 테마 이름, 화면 이름, 가져갈 부분이 모두 들어 있는지 봅니다.

## 막혔을 때

- **생성이 오래 걸리거나 한도 안내가 나온다** → 「Stitch 시작 가이드」의 막혔을 때를 봅니다. 시간이 모자라면 테마 2개 × 화면 2장(완료 기준의 최소)으로 줄입니다.
- **파일 첨부가 안 된다** → DESIGN.md를 메모장으로 열어 내용 전체를 복사해 `[디자인 규칙]` 아래에 붙여 넣습니다. 문서가 너무 길어 잘리면 색 · 글꼴 · 부품 · 하지 말 것 항목만 붙입니다.
- **테마끼리 거의 같아 보인다** → 두 DESIGN.md의 색 항목을 나란히 놓고 봅니다. 정말 비슷하면 「디자인 쇼핑처 둘러보기 가이드」로 돌아가 방향이 다른 문서로 하나를 바꿉니다.
- **매번 전혀 다른 배치가 나온다** → 화면 설명에 순서를 적습니다. 예) "위에서부터 {첫째}, {둘째}, {셋째} 순서로". 이 줄은 원본에 넣고 모든 테마에 똑같이 씁니다.
- **고칠수록 나빠진다** → 고치기를 멈추고 직전에 내보낸 이미지를 비교표에 씁니다. 남은 문제는 이유 칸에 적습니다.
- **DESIGN.md를 무시하는 것 같다** → "첨부한 DESIGN.md의 색·글꼴·모서리 규칙을 세 줄로 요약한 뒤 그 규칙대로 다시 그려 주세요."라고 지시해 Stitch가 문서를 읽었는지 먼저 확인합니다.
- 다음 단계인 클릭 프로토타입은 「Claude Code 프로토타이핑 따라 하기」로 이어집니다.
