# 디자인 스킬 가져오기 가이드

교재: 4.3절 외부 디자인 요소로 보강하기 · 지시문: 지시문 킷의 「외부 디자인 요소 보강 지시문」 · 바뀌는 파일: `prototype-merged.html`(복사본 `prototype-merged-before-skill.html`) · 쓰는 곳: 워크시트 문서 「테마별로 만든 첫 프로토타입과 버전 기록」의 "통합 프로토타입 + 디자인 스킬" 행

## 이 가이드에서 볼 것

- Claude Code는 디자인 스킬을 작업 폴더 안의 `.claude/skills/<스킬이름>/SKILL.md` 파일로 저장합니다. 저장되면 Code 탭 입력창에 `/`를 쳤을 때 목록에 이름이 보입니다.
- 가져온 지시문은 붙여 넣기 전에 **직접 끝까지 읽습니다.** 설치 명령이나 바깥 주소가 들어 있으면 그 부분은 쓰지 않습니다.
- 적용은 복사본을 만든 뒤, 영역 하나에만 합니다.

디자인 스킬이 무엇인지, 고르는 기준, 지시문 예시는 교재 4.3절에 있습니다. Code 탭 기본 조작은 「[Claude Code 프로토타이핑 따라 하기](claude-code-prototyping-guide.md)」와 부록 A-5를 봅니다.

## 어디서 가져오나

교재가 예로 든 곳은 Part 3에서 본 **21st.dev**입니다. 부품 화면마다 미리 보기와 **Copy prompt**(AI 도구에 붙여 넣을 지시문 복사) 버튼이 있습니다. 다른 쇼핑처는 「[디자인 쇼핑처 둘러보기 가이드](design-shopping-guide.md)」를 봅니다.

21st.dev의 부품은 대부분 React·Tailwind CSS 같은 개발 도구용 코드라서, 복사한 지시문에 설치 명령(`npm`, `npx`, `shadcn` 등)이 들어 있는 경우가 많습니다. 우리 프로토타입은 설치 없이 더블클릭으로 여는 HTML 한 파일이므로, 지시할 때 "설치 없이 HTML·CSS·JavaScript만으로 다시 만들어 줘"를 꼭 붙입니다.

## 안전하게 가져오기

1. **먼저 읽습니다.** 복사한 지시문을 메모장이나 텍스트 편집기에 붙여 끝까지 읽습니다. 설치·실행 명령, 바깥 주소(`http`로 시작하는 이미지·글꼴·스크립트 주소), "모든 파일"이나 "다른 폴더"처럼 범위를 넓히는 말, 뜻을 알 수 없는 긴 기호 덩어리가 있으면 그 줄은 지우고 씁니다.
2. **작업 폴더 안에만 저장합니다.** 스킬을 내 컴퓨터 전체에 쓰는 개인 스킬 위치(`~/.claude/skills/`)에 저장하겠다고 하면 거절하고 작업 폴더 안으로 지정합니다.
3. **모르는 스크립트는 받지 않습니다.** 스크립트 파일(`.sh`, `.js`, `.py` 등)이 함께 들어 있는 스킬 묶음은 내려받지 않고, 지시문 글만 가져옵니다.
4. **허락 요청을 읽습니다.** Claude Code가 설치나 명령 실행 허락을 물으면, 이번 실습에 필요한 일이 아니면 거절합니다(부록 A-5의 규칙과 같습니다).

## 따라 하기

### 1. 보강할 영역 하나 고르기

기준은 교재 4.3절 [실습 안내] ①입니다. 장점 찾기 표에서 모든 버전이 △나 —였던 영역, 버전 기록 "다음에 할 일"에 적어 둔 영역이 후보입니다. 하나만 고릅니다.

### 2. 요소를 고르고 지시문 복사, 출처 기록

1. 21st.dev 검색창에 영문 낱말(예: modal, stepper, calendar, progress)을 넣어 찾습니다.
2. 미리 보기에서 직접 눌러 보고, 내가 원하는 움직임인지 확인합니다.
3. **Copy prompt**로 지시문을 복사하고, 주소창의 부품 주소를 복사해 버전 기록 "근거" 칸에 붙여 둡니다.

버튼 위치는 「[디자인 쇼핑처 둘러보기 가이드](design-shopping-guide.md)」의 21st.dev 그림과 같습니다.

### 3. 저장하고 영역 하나에 적용하라고 지시하기

교재 4.3절 ③의 예시나 킷 기본형을 씁니다. 줄 범위는 **통합 프로토타입의 영역 지도**에서 가져옵니다(「[여러 버전 통합 가이드](version-merge-guide.md)」 5단계). 스킬 이름은 영문 소문자와 하이픈으로 짓습니다. 이 이름이 그대로 `/` 명령 이름이 됩니다. 아래 줄을 더해 보내면 저장 위치와 안전이 분명해집니다.

```text
- 스킬은 이 작업 폴더 안의 .claude/skills/{스킬이름}/SKILL.md 로 저장해 줘. 내 컴퓨터 전체에 저장하지 마.
- 설치 명령은 실행하지 말고, 바깥 주소에서 아무것도 불러오지 말고, HTML·CSS·JavaScript만으로 다시 만들어 줘.
- 색과 글꼴은 지금 prototype-merged.html 의 것을 따르고, 구조와 움직임만 가져와.
```

원래 지시문의 상품·사진 문구는 내 대상 객체로 **번역**해 지시합니다. 먼저 "원래 요소의 무엇 → 내 서비스의 무엇"을 한 줄씩 적어 보면 쉽습니다. 예) 상품 하나 → {대상 객체} 하나, 가격 → {속성}, 상품 사진 → 사진 없이 글자와 숫자. 넣을 속성은 내 프로필 CSV에 실제로 있는 열인지 자료실 「[프로필 데이터셋](../datasets/README.md)」의 열 이름 안내로 확인합니다.

### 4. 저장 확인

**이렇게 나오면 정상**
- Claude Code가 `.claude/skills/{스킬이름}/SKILL.md`를 만들겠다고 허락을 묻고, 만든 뒤 경로를 알려 줍니다.
- 입력창에 `/`를 치면 목록에 스킬 이름이 보입니다. 안 보이면 새 대화를 열고 다시 봅니다.
- SKILL.md 맨 위 `---` 두 줄 사이에 이름(name)과 설명(description)이 있고, 그 아래에 지시문이 있습니다.

`.claude`처럼 점으로 시작하는 폴더는 Mac Finder에서 숨은 폴더라 `Cmd+Shift+.`을 눌러야 보입니다. Windows 파일 탐색기에서는 보통 그대로 보이고, 안 보이면 보기 → 표시 → 숨겨진 항목을 켭니다. 또는 Claude Code에 "`.claude/skills` 폴더의 파일 목록과 SKILL.md 첫 10줄을 보여 줘. 고치지 마."라고 묻습니다.

### 5. 적용 결과 확인

**이렇게 나오면 정상**
- 폴더에 `prototype-merged-before-skill.html` 복사본이 생겼습니다.
- 복사본과 `prototype-merged.html`을 브라우저 두 창에 나란히 열면, 고른 영역만 다르고 나머지는 같습니다.
- 대화 끝에 바뀐 줄 범위가 있습니다.
- 브라우저 찾기(`Cmd+F`, Windows `Ctrl+F`)로 "상품", "가격", "장바구니", "Lorem"을 찾아도 나오지 않습니다.
- 모달이라면 닫기 버튼 · Esc 키 · 바깥 누르기로 직접 닫아 봅니다.

**다르게 나오면 이렇게 다시 지시합니다**
- 다른 영역도 바뀌었다 → "{영역 이름} 밖에서 바뀐 곳이 있어. prototype-merged-before-skill.html 과 비교해서 {영역 이름} 밖의 변경은 모두 원래대로 되돌려 줘."
- 원래 문구가 남았다 → "아직 '{남은 문구}'가 보여. 이 요소의 예시 문구를 모두 {대상 객체} 내용으로 바꿔 줘."
- 색이 혼자 튄다 → "새 요소의 색과 글꼴을 주변 카드와 같게 맞춰 줘. 구조와 움직임은 그대로 둬."
- 모달이 열리지 않거나 닫히지 않는다 → "{카드}를 눌러도 모달이 열리지 않아(또는 Esc로 닫히지 않아). 원인을 먼저 설명하고, 내가 승인하면 고쳐 줘."
- 처음부터 다시 하고 싶다 → "prototype-merged-before-skill.html 의 내용으로 prototype-merged.html 을 되돌려 줘. 복사본은 그대로 둬."

### 6. 버전 기록에 행 추가

"통합 프로토타입 + 디자인 스킬" 행에 교재 4.3절 ④처럼 적습니다. 바뀐 점에는 영역과 스킬 이름, 근거에는 불편 번호와 출처 주소, 다음에 할 일에는 사용성 점검에서 확인할 동작을 씁니다.

### 7. 다음에 이름만 불러 다시 쓰기

입력창 **맨 앞에** `/{스킬이름}`을 쓰고 이어서 적용할 곳을 적습니다. 예) `/workout-modal prototype-merged.html 의 {영역 이름}({시작}~{끝}줄)에 적용해 줘. 다른 영역은 고치지 마.` 문장 중간에 `/이름`을 쓰면 바로 실행되지 않습니다. 스킬 설명과 맞는 요청이면 Claude Code가 알아서 불러 쓰기도 합니다.

### 8. 다른 회사의 AI 코딩 도구를 쓸 때

스킬을 저장하는 기능의 이름과 위치는 도구마다 다릅니다. 어느 도구에서나 되는 방법은 지시문을 작업 폴더 안의 글 파일로 저장해 두고 가리키는 것입니다. "아래 지시문을 design/skill-{스킬이름}.md 로 저장해 줘"라고 한 뒤, 다음부터 "design/skill-{스킬이름}.md 의 지시를 따라 {영역 이름}에 적용해 줘"라고 그 도구의 파일 지정 방식으로 가리킵니다. Claude Code에서 `/` 목록에 스킬이 끝내 안 보일 때도 같은 방법을 씁니다.

## 자주 하는 실수와 고친 예

- **"이 디자인 적용해 줘"만 보냈다** (도서관 앱 예: 앱의 모든 카드가 바뀜) → 파일 이름과 줄 범위로 영역 하나만 지정합니다.
- **상품 카드 지시문을 그대로 썼다** (배달앱 예: 메뉴 카드에 "장바구니 담기 · 별점 4.8"이 남음) → "상품 하나 = 메뉴 하나, 별점은 빼기, 장바구니 담기 → 주문 목록에 넣기"로 번역해 지시합니다.
- **데이터에 없는 속성을 만들게 했다** (택배 앱 예: 기록에 없는 "배송 기사 평점"을 카드마다 넣음) → 데이터에 실제로 있는 속성만 넣습니다.
- **미리 보기 그림만 캡처해 붙였다** → 그림이 아니라 지시문을 복사합니다.
- **출처를 적지 않았다** → 근거 칸에 부품 주소를 남겨야 나중에 같은 요소를 다시 찾을 수 있습니다.

## 막혔을 때

- **`/` 목록에 스킬이 없다.** 새 대화를 열어 다시 봅니다. 작업 폴더가 `axyourbody-prototype`으로 열려 있는지, 파일 이름이 대문자 `SKILL.md`인지, 폴더 이름이 영문 소문자·하이픈인지 확인합니다. 그래도 없으면 8번 방법을 씁니다.
- **내 컴퓨터 전체 위치에 저장됐다.** "방금 저장한 스킬이 어디에 있는지 경로를 알려 주고, 이 작업 폴더의 .claude/skills/ 안으로 옮겨 줘."
- **설치 명령을 실행하겠다고 한다.** 거절하고 "설치는 하지 마. 이 파일 안에서 HTML·CSS·JavaScript만으로 같은 모양과 움직임을 만들어 줘."라고 다시 지시합니다.
- **Copy prompt 버튼이 없거나 복사가 안 된다.** 요소의 생김새와 움직임을 직접 글로 적어 지시합니다. 예) "누르면 커지면서 안쪽 항목이 작은 카드로 펼쳐지는 모달".
- **적용 뒤 다른 곳이 깨졌다.** 5단계의 마지막 문장으로 복사본 상태로 되돌린 뒤, 범위를 더 좁혀 다시 지시합니다.
- **스킬 내용을 고치고 싶다.** "{스킬이름} 스킬에 '{더할 규칙}' 규칙을 더해 줘."라고 지시하면 SKILL.md가 고쳐집니다.
- **사용 한도에 걸렸다.** 사전 안내의 조건에 맞는 다른 회사의 AI 코딩 도구로 같은 작업 폴더를 열고 8번 방법으로 이어 합니다.
