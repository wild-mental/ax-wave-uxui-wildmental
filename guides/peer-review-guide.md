# 동료 리뷰 진행 가이드

교재: 2.9절 동료 리뷰와 오늘의 정리 · 쓰는 곳: 워크시트 문서 `worksheet.md`의 「시스템 내부 용어와 사용자 용어를 맞춘 용어 대조표」의 리뷰 메모 칸

## 이 가이드에서 볼 것

짝과 서로의 용어 대조표를 읽어 주는 40분 남짓한 리뷰를 진행하는 순서, 두 사람이 말할 문장, 리뷰 메모를 쓰는 법, 하루를 마치기 전 확인할 것을 다룹니다. 리뷰의 다섯 단계 자체는 교재 2.9 본문을 봅니다.

## 진행 순서와 시간

아래에서 "설계자"는 자기 표를 보여 주는 사람, "짝"은 처음 보는 사람입니다.

| 순서 | 시간 | 설계자 | 짝 |
|---|---|---|---|
| 준비 | 5분 | 용어 대조표의 "사용자 용어"만 종이나 메모장에 옮겨 적습니다. 진입점 선택표의 메뉴 이름도 따로 적고, 찾기 질문 두 개를 만듭니다 | 내 표도 같은 방법으로 준비합니다 |
| 이름만 보여 주기 · 뜻 말하기 | 10분 | 이름 목록을 보여 주고, 짝의 말을 설명 없이 받아 적습니다 | 이름마다 "누르면 무엇이 나올 것 같은지" 한 문장으로 말합니다 |
| 어긋난 이름 표시 | 5분 | 내 의도와 다른 짐작을 리뷰 메모 칸에 적습니다 | 기다립니다 |
| 찾기 질문 두 개 | 5분 | 메뉴 이름만 보여 주고 질문합니다. 짝이 고른 메뉴를 적습니다 | 고를 메뉴를 말합니다 |
| 역할 바꾸기 | 20분 | 위 세 줄을 역할을 바꿔 반복합니다 | |
| (필요할 때만) 약식 카드소팅 | 15분 | 분류 기준이 계속 엇갈렸을 때만 합니다(교재 2.9). 이름 카드는 종이 쪽지나 Figma 스티키로 만듭니다 | 카드를 묶고 묶음에 이름을 붙입니다 |

**찾기 질문 만드는 법.** 과업·불편 목록의 우선순위 "상" 과업에서 상황을 빌려, 메뉴 이름을 쓰지 않고 묻습니다. 도서관 앱이라면 "빌린 책" 메뉴를 시험할 때 "반납일이 언제였는지 확인하려면 어디를 누르시겠어요?"처럼 묻습니다. 질문에 메뉴 이름이 들어가면 답을 알려 준 셈이 됩니다.

## 묻는 말 대본

**설계자가 하는 말**

- 시작: "제가 정한 이름만 보여 드릴게요. 설명은 하지 않을게요. 정답은 없으니 처음 보고 떠오르는 대로 말씀해 주세요."
- 이름마다: "이 이름을 보면 무엇을 짐작하나요? 누르면 무엇이 나올 것 같은지 한 문장으로 말해 주세요."
- 짐작이 짧을 때: "조금만 더 말해 주시겠어요? 무엇이 보일 것 같나요?"
- 찾기 질문: "{상황}에 {하려는 일}을 하려면 어느 메뉴를 누르시겠어요?"
- 끝: "고맙습니다. 어긋난 곳은 제가 고칠 부분이에요."
- 하지 않는 말: "아, 그게 아니라…", "이건 ~라는 뜻이에요". 설명하는 순간 이름이 혼자 서는지 알 수 없게 됩니다.

**짝이 하는 말**

- 짐작: "이걸 누르면 ~가 나올 것 같아요."
- 헷갈릴 때: "~와 ~ 사이에서 헷갈려요." / "이 말은 처음 봐요."
- 찾기: "저라면 ~를 누를 것 같아요. ~라는 말이 보여서요."
- 하지 않는 말: 새 이름을 지어 주거나 "이렇게 바꾸세요"라고 정해 주지 않습니다. 짝은 사용자 입장에서 답만 하고, 결정은 설계자가 합니다.

## 리뷰 메모 쓰는 법

용어 대조표에서 그 이름이 있는 줄의 리뷰 메모 칸에 **"상대의 짐작 → 내 결정(유지/변경)"** 순서로 씁니다(교재 2.9 [실습 안내]의 예). 짐작이 맞았던 이름도 "유지"로 남겨 두면 리뷰를 받았다는 기록이 됩니다. 관통 예제 밖의 예로 보면 이렇습니다.

| 사용자 용어 | 리뷰 메모 |
|---|---|
| 반납함 | 책을 넣는 상자가 있는 곳 같다고 함 → 변경: "반납 신청" |
| 빌린 책 | 지금 빌린 책 목록이 나올 것 같다고 함 → 유지 |
| 빌린 책 (찾기) | "반납일 확인" 질문에 "내 정보"를 고름 → 유지, 내 정보 안에 빌린 책으로 가는 길을 더함 |

변경한 이름은 같은 날 진입점 선택표와 서비스 구조 설명서 5·6절에도 고칩니다(「서비스 구조 설명서 작성 가이드」).

## 하루 마무리 확인

- [ ] 이벤트 보드(Figma)·대상 객체 카드·용어 대조표·진입점 선택표의 완료 기준 체크리스트와 서비스 구조 설명서를 확인했다
- [ ] 워크시트 저장소에 오늘 고친 것이 저장되었다: 저장소 첫 화면에서 `worksheet.md` 옆에 표시된 마지막 저장 시각이 오늘이고, 파일을 열었을 때 리뷰 메모가 보인다. 편집 화면에서 "Commit changes"를 누르지 않고 나왔다면 저장되지 않은 것입니다(부록 A-2, 「GitHub 워크시트 저장소 가이드」)
- [ ] 워크시트 저장소가 비공개(Private)이고, 저장소 설정(Settings)의 Collaborators에 강사의 GitHub ID가 들어 있다. 초대 대기(Pending)로 보이면 강사가 아직 수락하지 않은 것이니 그대로 두면 됩니다(부록 A-2)
- [ ] Figma 파일이 강사만 볼 수 있게 공유되어 있고, 그 링크를 `worksheet.md` 기본 정보의 "Figma 템플릿 링크 (강사만 열람)" 줄에 적었다(부록 A-3)

## 막혔을 때

- 짝의 짐작이 모두 맞아 고칠 것이 없으면, 찾기 질문을 하나 더 해 봅니다. 메뉴 사이의 경계는 이름 하나씩 볼 때보다 찾기에서 잘 드러납니다.
- 짝과 의견이 맞서면 그 자리에서 결론 내지 말고 짐작을 그대로 적은 뒤, 페르소나 카드의 "이 사람이라면 이렇게 말할 것"과 견줘 혼자 결정합니다.
- 바꿀 이름 후보가 떠오르지 않으면 Claude에 이렇게 묻습니다(부록 A-1): "아래 이름을 처음 본 사람이 '{짐작}'이라고 이해했어. 내가 뜻한 것은 '{뜻}'이야. 이 뜻이 분명히 드러나는 이름 후보를 세 개 주고, 각각 어떻게 오해될 수 있는지도 적어 줘."
- 용어 대조표의 칸 쓰는 법은 「용어 대조표 작성 가이드」를 봅니다.
