# 서비스 구조 설명서 작성 가이드

교재: 2.8절 Claude에 넘길 서비스 구조 설명서 미리 만들기 · 쓰는 곳: 워크시트 문서 `worksheet.md`의 「Claude에 넘길 서비스 구조 설명서」(진입점 선택표 다음)

## 이 가이드에서 볼 것

서비스 구조 설명서는 Day 2에 만든 워크시트를 1~8번의 글 한 편으로 묶은 것입니다. 이 가이드는 항목마다 어느 워크시트에서 옮기는지, Claude 점검 결과를 읽고 고치는 법, Day 3에 이 글을 작업 폴더로 넘기는 법을 다룹니다. 쓰는 규칙 네 가지와 작성 예시는 교재 2.8의 본문과 박준혁 예제를 봅니다.

## 템플릿에서 쓰는 곳

`worksheet.md`를 열고 연필 아이콘을 눌러 편집합니다(부록 A-2). 「Claude에 넘길 서비스 구조 설명서」 제목 아래, ` ```markdown `으로 열고 ```` ``` ````로 닫는 코드 상자 안에 1~8번 제목과 `{ }` 줄이 들어 있습니다.

- **코드 상자 안에만 씁니다.** 여는 줄과 닫는 줄의 ```` ``` ````는 지우지 않습니다. 상자 안에서는 글자가 쓴 그대로 보이므로, Day 3에 상자째 복사하기 좋습니다.
- **절 제목은 그대로 두고 `{ }` 줄을 내 내용으로 바꿉니다.** 내용은 한 줄에 한 가지씩 `- `로 시작하는 짧은 목록으로 쓰고(4번은 사건을 `→`로 잇습니다), 워크시트의 표를 그대로 붙이지 않습니다.
- 첫 줄 제목의 `{데이터셋 이름}`과 `{프로필 이름}`은 담당 가상 프로필의 ID와 이름으로 바꿉니다.
- 저장 전에 미리 보기(Preview) 탭에서 코드 상자가 끝까지 이어지는지(닫는 줄이 남아 있는지) 확인하고 "Commit changes"로 저장합니다.

**항목마다 옮겨 오는 곳** (교재 2.8 [실습 안내] 기준)

| 절 | 옮겨 오는 워크시트 | 옮기는 요령 |
|---|---|---|
| 1. 서비스와 사용자 | 설계 판단의 기준이 되는 타깃 사용자 페르소나 카드 | 한 줄 정체성과 핵심 과업 가운데 가장 중요한 것 하나 |
| 2. 대상 객체와 핵심 속성 | 서비스가 다루는 대상 객체·속성·관계를 정리한 대상 객체 카드 | 대상 객체 한 줄에 필수 속성, 괄호 안에 선택 속성 |
| 3. 관계 | 서비스가 다루는 대상 객체·속성·관계를 정리한 대상 객체 카드 | 관계 칸의 `1:N`·`N:M` 표시를 그대로 |
| 4. 사건 | 고객 여정 위에 사건과 대상 객체를 붙인 이벤트 보드(Figma)의 사건 레인 | 과거형 사건을 시간 순서대로 `→`로 잇기 |
| 5. 화면에 쓸 말 | 시스템 내부 용어와 사용자 용어를 맞춘 용어 대조표 | `시스템 내부 용어 = "사용자 용어"` 꼴로, 마지막 줄에 피할 말 |
| 6. 메뉴와 위치 표시 | 메뉴·진입점·위치 표시를 정한 길찾기 진입점 선택표 | 메뉴 개수와 순서, 위치 표시 방법, 메뉴에 올리지 않은 것과 찾는 곳 |
| 7. 검색·필터 | 메뉴·진입점·위치 표시를 정한 길찾기 진입점 선택표 | 검색·필터 항목 |
| 8. 하지 말 것 | 옮겨 올 워크시트가 없습니다 | 교재 2.8의 규칙과 박준혁 예제를 보고 내 서비스에 맞게 직접 씁니다 |

2.9 동료 리뷰에서 이름이 바뀌면 용어 대조표를 먼저 고친 뒤 5·6번에도 같은 이름으로 반영합니다.

## Claude 점검 결과 읽는 법

교재 2.8의 점검 지시문을 새 대화에 붙여 넣으면 "세 줄 설명"과 "질문"이 돌아옵니다(부록 A-1).

**세 줄 설명**은 내 설명서가 남에게 어떻게 읽히는지 보여 줍니다. 세 가지를 견줘 봅니다.

- 사용자: 세 줄에 나오는 사람이 내 페르소나와 같은 사람인가?
- 가장 중요한 과업: 1번에 쓴 과업이 세 줄 안에 들어 있는가?
- 이름: 세 줄에 쓰인 말이 5번의 "사용자 용어"인가, 시스템 내부 용어나 피할 말인가?

어긋난 곳이 있으면 그 내용이 들어 있는 절을 고칩니다. 예를 들어 과업이 빠졌으면 1번, 피할 말이 나왔으면 5번입니다.

**질문**은 한 개씩 세 갈래로 나눕니다.

| 질문의 종류 | 할 일 |
|---|---|
| 설명서에 이미 답이 있는데 물었다 | 그 답이 있는 절의 문장을 더 짧고 분명하게 고칩니다 |
| 아직 정하지 않은 것을 물었다 | 지금 정해서 맞는 절에 한 줄 더합니다. 대상 객체·관계는 대상 객체 카드, 이름은 용어 대조표에 먼저 쓰고 옮깁니다 |
| 화면의 배치·색·문구 길이처럼 Day 3에 정할 것을 물었다 | 지금은 고치지 않고 메모만 해 둡니다 |

고친 뒤에는 새 대화에서 같은 지시문으로 한 번 더 점검합니다. 같은 대화에서 이어 물으면 앞의 답에 기대어 읽기 때문입니다.

## 자주 하는 실수와 고친 예

- **워크시트 표를 통째로 붙였다** → 한 줄에 한 가지만 쓰는 목록으로 바꿉니다(교재 2.8 규칙 ①).
- **5번에 피할 말이 없다** (도서관 앱 예: `대출 기록 = "빌린 책"`만 있음) → 마지막 줄에 `피할 말: 대출 이력, 히스토리`처럼 같은 뜻으로 쓰지 않을 말을 적습니다.
- **같은 것을 항목마다 다르게 불렀다** (2번 "주문", 4번 "주문서가 생성됨", 6번 "내 주문 목록") → 2번의 대상 객체 이름을 기준으로 맞추고, 화면에 다르게 보일 이름은 5번에만 적습니다.
- **6번에 메뉴를 늘어놓기만 했다** → 메뉴가 몇 개이고 어떤 순서인지, 지금 있는 곳을 색 말고 무엇으로 알리는지까지 씁니다.
- **실제 이름이나 실제 신체 수치가 들어갔다** → 지우고 가상 프로필 ID만 남깁니다(교재 2.8 규칙 ④). 이 글은 Day 3에 AI 도구에 그대로 넘어갑니다.

## 완료 기준 체크리스트 확인 방법

| 체크리스트 항목 | 이렇게 확인합니다 |
|---|---|
| 8개 항목을 모두 채웠다 | 코드 상자 안에 `{`나 `}`가 하나도 남아 있지 않고, 1~8번 제목 아래마다 내 내용이 한 줄 이상 있습니다. 4번은 사건이 `→`로 이어져 있습니다 |
| 이 설명서만 읽어도 대상 객체와 화면 이름을 알 수 있다 | Claude의 세 줄 설명이 내 의도와 맞습니다. 그리고 화면에 나오는 대상 객체마다 5번에 화면 이름이 있고, 6번의 메뉴 이름이 모두 용어 대조표의 사용자 용어에 있는 말입니다 |

## Day 3에 넘기는 법 (미리 보기)

Day 3에는 이 설명서를 작업 폴더 `axyourbody-prototype/`의 `context/service-structure.md` 파일로 저장합니다(부록 A-5).

1. GitHub에서 `worksheet.md`를 열고(편집 화면이 아닌 파일 화면), 설명서 코드 상자 오른쪽 위의 복사 단추를 누릅니다. 편집 화면에서 복사할 때는 상자의 첫 줄(` ```markdown `)과 마지막 줄(```` ``` ````)을 빼고 그 사이만 복사합니다.
2. 작업 폴더의 `context` 폴더에 `service-structure.md` 파일을 만들어 붙여 넣고 저장합니다. 파일을 만들기 어렵다면 Claude Code에 "context 폴더에 service-structure.md 파일을 만들고 아래 글을 고치지 말고 그대로 넣어 줘"라고 지시한 뒤 글을 붙여 넣습니다.
3. 파일 이름이 `service-structure.md.txt`처럼 바뀌지 않았는지, 파일을 열었을 때 1번부터 8번까지 다 들어 있는지 확인합니다.

설명서를 고칠 일이 생기면 `worksheet.md`를 먼저 고치고 다시 복사합니다. 두 곳을 따로 고치면 어느 쪽이 최신인지 알 수 없게 됩니다.
