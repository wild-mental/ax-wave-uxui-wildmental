# 디자인 쇼핑처 둘러보기 가이드

교재: 3.4절 디자인 쇼핑으로 DESIGN.md 2~3종 고르기 · 쓰는 곳: 워크시트 문서의 「참고할 AI 디자인 가이드(DESIGN.md) 후보 쇼핑 목록」 → 3.6에서 작업 폴더의 `design/DESIGN-<테마이름>.md`

## 이 가이드에서 볼 것

교재 3.4의 「다섯 군데 쇼핑처」 표에 무엇을 사는 곳인지와 가져올 단위가 있습니다. 이 가이드는 그 다섯 곳에서 **어디를 눌러 무엇을 고르고, 무엇을 들고 나오는지**만 다룹니다. 고르는 기준(프로필에 맞는 톤)과 쇼핑 목록 칸 설명은 교재 3.4의 「쇼핑 기준」 표와 [실습 안내]를 봅니다.

핵심 세 가지:

1. DESIGN.md 파일은 **getdesign.md**에서 받거나 디지털 킷의 [샘플 DESIGN.md](../kits/DESIGN-axyourbody-sample.md)를 씁니다. 나머지 네 곳은 문서에 덧붙일 **조각**(흐름 아이디어, 부품, 로고 형태, 기본 규칙)을 사는 곳입니다.
2. 들고 나오는 것은 파일 하나 또는 **글로 적은 메모**입니다. 남의 이름·로고·그림은 들고 나오지 않습니다.
3. 둘러본 곳의 주소는 바로 쇼핑 목록의 출처 칸에 붙여 둡니다. 나중에 다시 찾기 어렵습니다.

사이트 화면과 메뉴 이름은 자주 바뀝니다. 아래 메뉴 이름이 보이지 않으면 비슷한 이름을 찾거나 사이트 안의 검색을 씁니다. KRDS를 뺀 네 곳은 영어 사이트입니다. 브라우저의 번역 기능을 켜고 둘러봐도 됩니다.

## 시작 전 준비

- 내 워크시트 저장소의 `worksheet.md`에서 「참고할 AI 디자인 가이드(DESIGN.md) 후보 쇼핑 목록」을 열어 두고, 맨 위에 내 프로필의 톤과 확인할 것을 옮겨 적습니다(교재 3.4 작성 순서 1번).
- 내려받은 파일을 모을 폴더를 하나 정합니다. 3.6에서 `axyourbody-prototype/design` 폴더로 옮기므로, 작업 폴더를 미리 만들었다면 처음부터 `design` 폴더에 저장해도 됩니다.

## getdesign.md — DESIGN.md 문서 고르기

**가는 길.** `https://getdesign.md`에 들어가면 서비스 분위기별 DESIGN.md 목록(catalog)이 나옵니다. 위쪽 분류(예: 개발 도구, 금융, 쇼핑, 자동차)로 좁혀 볼 수 있습니다. 둘러보기와 내려받기는 로그인 없이 됩니다. 로그인은 마음에 드는 문서를 저장(bookmark)할 때만 필요합니다.

**고르는 법.**

1. 목록에서 문서 하나를 누르면 그 문서 화면이 열립니다. 위쪽의 **Preview**(미리 보기)로 이 규칙을 적용한 화면 예를 보고, **DESIGN.md** 탭으로 문서 본문을 봅니다.
2. 본문은 보통 개요(Overview) · 색(Colors) · 글꼴(Typography) · 배치(Layout) · 그림자(Elevation) · 부품(Components) · 반응형(Responsive Behavior) 순서입니다. 교재 3.4의 요령대로 **색 항목과 "하지 말 것"에 해당하는 내용**을 먼저 읽습니다.
3. 미리 보기 화면에서 주요 버튼이 몇 개인지, 숫자와 글자 중 무엇이 먼저 눈에 띄는지 봅니다. 내 프로필의 "고를 때 확인할 것"에 답하는지가 기준입니다.
4. 서로 다른 방향으로 2~3개를 고릅니다. 비슷해 보이는 두 문서라면 색 항목을 나란히 놓고 비교한 뒤 하나만 남깁니다.

> [캡처 예정] 공통: 문서 화면의 Preview · DESIGN.md 탭과 내려받기 버튼 위치

**내려받기와 이름 바꾸기.**

1. 문서 화면의 **Download DESIGN.md** 버튼을 누릅니다. 파일은 브라우저의 다운로드 폴더에 `DESIGN.md` 같은 이름으로 저장됩니다. 화면에 보이는 `npx …` 명령은 쓰지 않아도 됩니다.
2. 파일 이름을 `DESIGN-<테마이름>.md`로 바꿉니다(교재 3.4 작성 순서 3번). 테마 이름은 영문 소문자와 하이픈만 씁니다. Mac은 파일을 고르고 `Return`, Windows는 `F2`를 누르면 이름을 고칠 수 있습니다.
3. 파일을 메모장(Windows)이나 텍스트 편집기(Mac)로 열어 맨 위 제목과 본문에 나오는 **원래 서비스 이름을 지웁니다.** 제목은 `# DESIGN.md — <DESIGN.md 이름>`처럼 쇼핑 목록에 적은 느낌 이름으로 바꿉니다. 손으로 고치기 어려우면 3.6에서 Claude Code에 "이 파일에서 특정 서비스 이름과 로고 설명을 모두 지우고, 제목을 '{DESIGN.md 이름}'으로 바꿔 줘. 색·글꼴·간격 규칙은 바꾸지 마."라고 맡깁니다.
4. 문서가 영어여도 그대로 씁니다. Stitch와 Claude Code는 영어 문서를 잘 읽습니다.

**메모해 올 것.** 쇼핑 목록의 출처 칸에 `getdesign.md · <문서 화면 주소>`를 적습니다.

## 디지털 킷의 샘플 DESIGN.md — 안전한 선택

자료실의 [샘플 DESIGN.md](../kits/DESIGN-axyourbody-sample.md)는 이 수업을 위해 새로 쓴 문서라 지울 서비스 이름이 없습니다. 열어서 오른쪽 위의 원본 보기(Raw) 화면에서 전체를 복사해 새 파일로 저장하거나, 저장소 화면의 내려받기 버튼으로 받습니다. 이름은 다른 후보와 똑같이 `DESIGN-<테마이름>.md`로 바꿉니다(교재 예: `DESIGN-neat-basic.md`).

- 샘플은 교재 3.3절 표와 같은 순서(분위기와 원칙 · 색 · 글꼴 · 간격과 배치 · 모양 · 부품 · 문구 톤 · 하지 말 것)로 쓰여 있고, 화면 구조는 정하지 않습니다. 화면 구조는 내 `screen-flow.md`를 따릅니다.
- 방향이 다른 후보가 하나 더 필요하면 [디자인 B 버전](../kits/DESIGN-axyourbody-sample-B.md)을 씁니다. B 버전은 상단 바·보조 영역·하단 고정 AI 코치 입력창 같은 **화면 구조까지 정해 둔** 문서입니다. 쓰기 전에 그 화면 구조(3번)가 내 `screen-flow.md`의 화면 목록과 맞는지 보고, 맞지 않으면 3번을 지운 뒤 저장합니다.

## UXSnaps — 쓰기 편한 흐름 아이디어

**가는 길.** `https://uxsnaps.com`. 유명 앱의 화면 하나나 과업 하나를 짧게 뜯어본 분석(lesson)이 카드로 나열됩니다. 앱 이름이나 주제(예: 온보딩, 입력, 알림)로 걸러 볼 수 있습니다.

**고르는 법.** 내 과업·불편 목록의 불편 하나를 떠올리고, 그 불편과 비슷한 장면(예: 기록을 빨리 남기기, 빈 화면에서 다시 시작하기)을 다룬 분석을 두세 개만 읽습니다. 화면이 예쁜 것보다 **몇 번 눌러서 끝나는지, 무엇을 미리 채워 두는지**를 봅니다.

**메모해 올 것.** 흐름·배치 아이디어를 한 줄로 적습니다. 예) "입력칸 대신 자주 쓰는 값 버튼 3개를 먼저 보여 줌 → 두 번 눌러 기록 끝". 화면 캡처나 앱 이름은 DESIGN.md에 넣지 않습니다. 이 메모는 바탕 문서의 "추가 규칙"(아래)이나 3.6의 수정 지시에 씁니다.

## 21st.dev — 부품 하나 고르기

**가는 길.** `https://21st.dev` → 위쪽 **Components**(부품). 왼쪽 분류나 위쪽 검색창(`K` 단축키)에서 영어 이름으로 찾습니다. 예) 진행 막대는 `progress`, 달력은 `calendar`, 카드는 `card`, 입력 양식은 `form`.

**고르는 법.** 부품을 누르면 움직이는 미리 보기가 나옵니다. 모바일 폭에서도 쓸 만한지, 색을 빼도 모양으로 읽히는지 봅니다. 부품 하나만 고릅니다.

**저장 목록과 지시문 복사.** 마음에 드는 부품은 **Bookmarks**(저장 목록)에 모아 둘 수 있습니다(로그인 필요). 부품 화면의 **Copy prompt**(지시문 복사)는 AI 코딩 도구에 그 부품을 만들게 하는 영어 지시문을 복사해 줍니다. 무료로 복사할 수 있는 횟수가 하루에 정해져 있으니 꼭 필요할 때만 씁니다.

**메모해 올 것.** 복사한 지시문이나 코드를 DESIGN.md에 그대로 붙이지 않습니다. 부품의 모양과 쓰임을 **글로** 옮깁니다. 예) "진행 막대: 굵은 막대 한 줄, 끝에 '몇 회 중 몇 회' 글자, 완료한 칸은 색과 빗금을 함께 쓴다". 출처 칸에는 부품 화면 주소를 적습니다.

## Logo System — 로고 형태 아이디어만

**가는 길.** `https://logosystem.co` → **Gallery**. 종류(Type: 기호, 글자, 기호+글자), 업종(Industry), 스타일(Style), 모양(Shape), 색(Color), 분위기(Mood) 필터를 겹쳐 고를 수 있습니다. 예) Shape에서 원형, Mood에서 친근함.

**고르는 법과 메모.** 4.5절에서 파비콘을 만들 때 쓸 **형태의 방향**만 적습니다. 예) "둥근 원 안에 머리글자 하나", "선 두께가 일정한 단순한 기호". 로고 그림을 내려받거나 따라 그리지 않습니다. 사이트도 로고마다 원작자 링크를 달고, 영감 참고용이라고 밝힙니다.

## KRDS — 기본 규칙 옮겨 적기

**가는 길.** `https://www.krds.go.kr` (한국어). 위쪽 메뉴에서 쓸 곳은 세 군데입니다.

| 찾는 것 | 메뉴 |
|---|---|
| 입력칸 이름 위치, 필수 표시, 도움말 | 기본 패턴 → 입력 폼 |
| 오류 메시지를 어디에 어떻게 보여 주는가 | 기본 패턴 → 오류 |
| 글자 크기 단계, 색 대비 | 디자인 스타일 → 타이포그래피 · 색상 |

**고르는 법.** 페이지 전체가 아니라 **내 화면에 생길 장면** 하나만 찾습니다. 예) 기록 입력에서 숫자를 잘못 넣었을 때. 그 장면의 규칙을 두세 줄만 고릅니다.

**옮기는 법.** 규칙을 내 말로 줄여 바탕 문서의 "추가 규칙"에 적고, 끝에 그 페이지 주소를 붙입니다. 링크만 적어 두고 "이 페이지의 규칙을 따른다"고 써도 되지만, 3.6에서 Claude Code가 그 페이지를 매번 다시 읽어야 하므로 꼭 필요한 규칙은 글로 옮겨 두는 편이 결과가 일정합니다.

## 가져오면 안 되는 것

| 가져오지 않는 것 | 대신 가져올 것 |
|---|---|
| 실제 서비스 이름 (파일 이름, 문서 제목, 본문) | 느낌을 나타내는 이름과 테마 이름 |
| 로고, 아이콘 세트, 마스코트, 일러스트 | 형태의 방향을 적은 한 줄 |
| 남의 화면 캡처를 DESIGN.md나 프로토타입에 넣기 | 흐름·배치 아이디어를 적은 한 줄 |
| 부품의 코드나 영어 지시문을 문서에 통째로 붙이기 | 부품의 모양과 쓰임을 적은 두세 줄 |
| 회사 고유의 글꼴 이름 | "둥근 고딕 계열"처럼 계열과 크기 단계 |

## 부품·색만 가져올 때: "추가 규칙" 붙이기

교재 3.4 작성 순서 4번처럼, 바탕이 될 DESIGN.md 맨 끝에 제목을 하나 달고 가져온 조각을 글로 덧붙입니다. 형식은 아래와 같습니다. `{ }`는 자기 내용으로 바꿉니다.

```markdown
## 추가 규칙
- {부품 이름}: {모양} · {언제 쓰는지} (출처: {쇼핑처 이름} · {주소})
- {장면}: {규칙 한 줄} (출처: KRDS {메뉴 이름} · {주소})
- 색만 가져온 경우: 주색 {색 값}, 주의 {색 값}. 원래 문서의 색 항목보다 이 줄을 먼저 따른다.
```

- 한 줄에 규칙 하나만 씁니다.
- 원래 문서의 규칙과 부딪히면 어느 쪽을 따를지 그 줄에 적습니다(위 마지막 줄처럼).
- 색으로만 상태를 구분하는 문서라면 라벨·아이콘 규칙을 이 자리에 한 줄 더합니다(교재 3.4 요령).

## 자주 하는 실수와 고친 예

- **같은 방향의 문서를 셋 골랐다** (도서관 앱 예: 흰 바탕에 파란 버튼인 문서 세 개) → 하나만 남기고, 색이 강한 것 하나와 단정한 것 하나로 바꿉니다.
- **파일 이름에 서비스 이름이 남았다** (`DESIGN-<서비스이름>.md`) → 테마 이름으로 바꾸고, 문서 제목과 본문의 이름도 지웁니다.
- **파일이 `DESIGN-neat-basic.md.txt`가 됐다** → 확장자가 숨겨져 있던 것입니다. Mac은 Finder 설정 → 고급 → "모든 파일 확장자 보기", Windows는 파일 탐색기 보기 → 표시 → "파일 이름 확장명"을 켜고 `.txt`를 지웁니다.
- **출처 칸에 사이트 이름만 적었다** ("21st.dev") → 고른 부품 화면의 주소까지 적습니다. 4.2에서 다시 찾을 때 씁니다.
- **고른 이유가 "예뻐서"** → 프로필의 원하는 한 문장이나 불편 번호와 이어 다시 씁니다.

## 완료 기준 체크리스트 확인 방법

- [ ] **DESIGN.md를 2개 이상 골랐다** → 쇼핑 목록의 행 수와, 내 폴더에 있는 `DESIGN-` 파일 수가 같은지 셉니다.
- [ ] **고른 이유를 프로필의 원하는 한 문장 또는 불편과 연결했다** → 고른 이유 칸마다 원하는 한 문장의 낱말이나 불편 번호가 들어 있는지 봅니다.
- [ ] **고른 파일을 `DESIGN-테마이름.md`로 이름을 바꿔 저장했다** → 파일 이름의 테마 이름이 쇼핑 목록 첫 칸과 글자 하나까지 같은지, 끝이 `.md`인지 확인합니다.

## 막혔을 때

- 사이트가 열리지 않거나 메뉴가 다르면 다른 쇼핑처로 넘어갑니다. DESIGN.md가 하나도 없으면 샘플 DESIGN.md 하나에 KRDS 규칙을 더한 문서를 안전한 선택으로 두고, getdesign.md는 다시 시도합니다.
